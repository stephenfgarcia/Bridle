# Change log: first synthesis to final

- R1-M1 (Tier-M 300 ms undeived): replaced the DOF-defined live promise with a live band defined by predicted work from the symbolic analysis both sides run (flops <= 2e8, DOF <= 6,000, cases <= 24, combinations <= 60); Tier-M models above the band run in Run mode with progress (3 s target, 5 s budget); the R14 contract attaches to two committed reference scenes (S-ref roof truss, M-ref 10-storey 6x6 frame at 3.2k DOF and 20 combinations); combinations are superposed on demand; the week-1 spike measures M-ref and M-cap on M1/Safari and Tiger Lake/Chrome; proposed ADR amendment A1 (sections 2, 4.2, 7, 8).
- R1-M2 (incremental vs fresh solve bit-identity): added the fresh-equivalence invariant (re-assemble K from the canonical list every solve; reuse ordering only when the adjacency graph is unchanged; reuse the numeric factor only when the assembled K is byte-identical), a freshSolve protocol op used at submit to compute client_result_hash and result_summary, a 1,000-op-sequence property test on all five wasm hosts, and result_match kinds that treat a same-artifact sub-tolerance difference as a metric with a 0.1 percent rate alert and page only on beyond-tolerance mismatches (sections 4.2, 7, 10).
- R1-M3 (within_tolerance not computable from a hash): defined the canonical result_summary document (per-combination reactions and residuals, per-node max translation with governing combination, per-member governing utilization, combination, station, limit state and N/V/M envelope; about 300 KB JCS at Tier M) computed by freshSolve, included in the bundle with its hash and compared value by value when artifacts or hashes differ; the comparison kind is recorded on the grade (sections 5, 6, 10, 11).
- R1-M4 (quantization vs solver input, missing quanta, overflow): stated the analysis-input invariant dequantize(canonicalize(model)) on both sides with a golden test, added per-field quanta for Cw (1e-18 m6), thermal expansion (1e-12 per K), temperature gradient (1e-6 K/m), strain and damping (1e-9), made any numeric field without a quantum a CI failure (schema walk test) and any count with |n| >= 2^53 a canonicalization error (section 6).
- R1-M5 (JCS result canonical form is 30-80 MB): the result canonical form is now a binary frame (JCS header plus int64 little-endian arrays in canonical order, per-case results plus per-member envelopes, per-combination station results excluded) hashed in about 100 ms; storage keeps a varint plus zstd generating set (per-case nodal displacements and reactions, about 0.6 MB at the M cap) and regenerates derived results under the pinned artifact; full frames persist only when a grade references them; sizes and times are stated in sections 6 and 10.
- R1-M6 (runner spawn compiles the modules per job): bridle-runner gained a serve mode, one warm process per worker slot that loads modules once from a cwasm cache keyed by artifact digest, wasmtime version and target CPU (populated at promotion) and serves jobs with a fresh Store, fresh memory and a fresh epoch deadline each; fuel is the deterministic meter, epoch the wall limit; the one-shot mode stays for CLI and support; burst arithmetic re-derived with a 2 s planning value per M-cap job to be replaced by measurement (sections 4.5, 4.11, 12).
- R1-M7 (judge latency and rate limits unmeasured): added a measurement gate in the first week of step 10 (50 golden grades live at concurrency 12 at effort medium and high) that feeds the burst table, SLO, budgets and OPS-12 ETA; restated the SLO as deterministic 100 percent within 10 min and judged 95 percent within 60 min pending measurement; formative judged stages moved to Message Batches; the Opus 5.5 tier increase is requested from measured per-minute token needs; the k6 rehearsal includes a live-judge slice; fast mode is evaluated as an optional lever only (sections 4.7, 4.14, 10, 12).
- R1-M8 (cross-host gate only runs the dense path): the engine promotion gate now runs on a determinism corpus that includes the S-ref, M-ref and M-cap scenes, all eight templates at S and M, three ill-conditioned fixtures and a nightly seeded 1,000-model random corpus on Node, Wasmtime, Chromium, Firefox and WebKit; native stays informational (sections 4.11, 7).
- R1-M9 (no write-rate model; per-op rows and 5-second segments): removed per-op rows (ops live only inside segments), moved the segment cadence to 30-60 s with flush on blur, hide and submit, stored open-session segments as zstd bytea rows in daily Postgres partitions with 15-minute rollups to content-addressed S3 objects, banned per-live-solve events in favour of client-side RUM batches, wrote the write-rate model (about 5.5 segment inserts per second at the 500-session target) and moved RDS to db.m7g.large Multi-AZ tested with k6 on the production class (sections 4.1, 4.8, 4.12, 5, 14).
- R1-M10 (15 percent wall-clock gate is flaky on CI): wasmtime fuel consumed per benchmark is the primary performance regression metric (gate 5 percent, deterministic for a pinned wasmtime version); wall-clock is informational on CI; a weekly job on a self-hosted M1 Mac mini (Safari and Chrome) and a Tiger Lake laptop runs the reference scenes and publishes the R14 evidence before the pilot (sections 4.16, 7, 15).
- R1-m1 (cancel latency without SharedArrayBuffer): the solve is structured as resumable phases held in wasm memory with the worker returning to its event loop between phases, so cancel and newer-seq messages are observed within about 50 ms; terminate() is reserved for panics (section 4.2).
- R1-m2 (20 ms scene rebuild contradicts the 16 ms Long Tasks assertion): overlay buffer rebuilds are chunked across frames; the assertion is 16 ms for engine message handling and 50 ms (SBX-01) for scene work (sections 4.2, 4.3).
- R1-m3 (transferring every case per edit): per-case results stay in the worker; only the active case or combination overlay and the per-member envelope summary are transferred; combinations are superposed on demand; live cases and combinations are capped by the live band (sections 4.2, 8).
- R1-m4 (native replay cannot assert hash equality): bridle-cli replay is an orchestration command that drives bridle-runner (wasm by pinned digest) for S1 and S2 and the TypeScript grader for S4; native is bench-only; canon-node loads engine.wasm by the task's pinned engine_ref and canon_version rather than one global digest (sections 4.10, 10).
- R1-m5 (unbounded greedy auto-sizing): calibration runs in the analyze lane with a bounded search (monotone within a section family, symbolic reuse across iterations, stop at DC >= 0.7 for the heaviest member per group) and stated budgets of 30 min at Tier S and 2 h at Tier M, with measured time in the calibration report (sections 5, 12, 17 step 8).
- R1-m6 (cache TTL economics): the cost basis is the cold task cache (median) and the regeneration path (p95); the cache-share alert is scoped to deadline windows and tasks with >= 12 grades in the hour; the task block is promoted to the 1-hour TTL whenever the task had a grade in the last hour (sections 10, 14).
- R1-m7 (SSE fan-out unspecified): one LISTEN/NOTIFY connection per web task fed by a grading_jobs trigger and the outbox relay, in-process fan-out, 25 s keepalives, ALB idle timeout 3,600 s, Last-Event-ID replay, 5 streams per user and a polling fallback; no stream polls Postgres (sections 4.1, 11, 13, 15).
- R2-M1 (121 ew in eight months is not credible): re-estimated every step (165 ew with the cut list applied by default, 189 ew at full scope), applied a 0.7 focus factor, added a contracted Rust/FE engineer for months 1-6 so solver and pack overlap, named owners per step, committed to a spring-2028 pilot with production-ready 2027-12-01 and a summer-2027 formative-only friendly alpha, and wrote a dated critical path with monthly milestones; proposed ADR amendment A4 (sections 1, 2, 17).
- R2-M2 (US pack is 20-30 ew, not 10): cut the MVP resistance pack to AISC 360-22 LRFD W-shapes (D2, E3, F2 compact, G2, H1, B4.1 classification with noncompact and slender shapes refused, slenderness advisories) with HSS, pipe, E4, F3, F6 and ASD as pack minors after the pilot; the pack is delivered incrementally (loads month 6, checks month 8, SME record month 9); the runnable partial-factor conformance pack became paper fixtures with the runnable pack moved to the NSCP sprint; SME framework agreements and the AISC request start at M0; estimate 20 ew; proposed ADR amendment A2 (sections 2, 7, 9, 17).
- R2-M3 (solver 10 ew is 16-20): estimate 18 ew; the spike also confirms a fill-reducing ordering on wasm32 and the fallback decision is time-boxed to day 5; the in-house fallback is sized at about 3k lines including AMD; symbolic reuse for drags, Timoshenko and the animated null-space mode are deferred to v1.1 if the spike slips; benchmarks and golden vectors come first (sections 7, 17, 18).
- R2-M4 (workspace 13 ew is 25-35): estimate 26 ew split into parity-first core, 3D tools and overlays; instancing and BVH picking from day one; extruded sections, named views, radial arrays, multiple probes and the snapshot title block deferred to v1.1 (sections 4.3, 17, 20).
- R2-M5 ($0.14 median omits cache writes and assumes 5.5k output): re-costed at the cold task cache with cache-write prices ($5 and $8 per MTok) and 8-12k output tokens at effort high: about $0.25 median and $0.50 p95, $0.18 at effort medium if the gates hold, $0.12 for formative through Batches; COST-02's $0.15 is stated as conditional on measured output; tenant budgets are sized from the measured p95 with a 1.5x margin; max_tokens raised to 16,000 with streaming; effort pinned explicitly because the model default is medium (sections 4.14, 10, 14).
- R2-M6 (30 s judge call and 21-minute burst unmeasured): same resolution as R1-M7; the burst runbook's first action is deferring formative judged stages to Batches, then scaling (sections 4.15, 12).
- R2-M7 (no launch budget or external-dependency calendar): added a one-time launch budget (counsel $25-45k, SME verification $25-50k, pentest $15-30k, WCAG audit $5-15k, insurance $8-20k per year, perf runners $2-3k; about $80-160k plus insurance) and a dated calendar with counsel, AISC and ACI requests and SME agreements at M0, DMCA registration and register determinations by M3, pentest booked by M4 for October, pilot agreement template by M6, insurance bound and agreement signed by M9, pentest, WCAG audit, HECVAT Lite and DPIA at the M11 code freeze (sections 14, 17).
- R2-M8 (run model is an unbudgeted FTE): carried an explicit 0.75 FTE run and support allocation per pilot term; deadline windows derive only from summative activities with >= 25 affected learners and are merged per tenant; the manual burst control is complemented by calendar-driven scheduled capacity executed by the system entrypoint (audited as policy, no autoscaler judgment); single-admin break-glass rollback inside windows with next-business-day review; transient dead-letter auto-replay pulled into MVP (sections 1, 4.8, 4.11, 4.15, 12, 13, 14).
- R2-M9 (S3 PUT cost of 5-second segments; erasure with shared objects): resolved with R1-M9 (Postgres segment rows, 15-minute S3 rollups, about 0.3 PUT per second at the target) plus a blob_refs reference table so content-addressed objects shared by two learners are deleted only when the last reference is gone and erasure is safe (sections 4.12, 4.13, 5, 13).
- R2-M10 (content is the hidden critical path): task, rubric and deliverable schemas freeze at the month-3 contracts milestone with fixtures; a content pipeline milestone at month 6 runs S0, S1, partial S2 and S4 deterministic-only on all templates in staging with golden-submission capture; full checks at month 9; the content track has its own owner (design-partner instructor plus SMEs) and the six-week buffer is counted backwards from the term (sections 6, 9, 17).
- R2-M11 (pinned model ids retire; no provider seam): added the model-deprecation runbook (pins-only task versions with the successor, harness re-run, judged criteria declared non-replayable, appeals routed to manual judging with deterministic criteria recomputed and judged scores carried, provider deprecation policy in the procurement pack) and the packages/grader/judge-client seam with record/replay fixtures as its contract (sections 4.7, 4.14, 4.15, 10, 18).
- R2-m1 (db.t4g.medium is sized for idle): moved to db.m7g.large Multi-AZ (about $300 per month) and required the k6 burst on the production instance class before the pilot; cost table recomputed to about $870 per month (sections 2, 4.12, 14, 15).
- R2-m2 (worker memory arithmetic and Fargate tmpfs): worker tasks are 2 vCPU/8 GB, job directories live on task ephemeral storage with a 64 MB cap and no tmpfs; the memory arithmetic is written down (sections 4.5, 4.6, 15).
- R2-m3 (SSE change source, ALB timeout, reconnect): resolved with R1-m7 (section 4.1).
- R2-m4 (hidden sets generated on first open): ReferenceAnswerSet, CheckKey and the auto-sized reference are generated at activity release for enrolled learners and at enrollment, cached by (task_version_id, seed), with on-demand generation only as the fallback (sections 4.6, 5).
- R2-m5 (checks and scene parts of the live budget unmeasured): the spike measures checks and scene rebuild on the reference laptop; live checks run one debounce behind the solve so the R14 contract covers solve plus render with utilization within about 200 ms (sections 4.2, 8).
- R2-m6 (12-minute PR checks optimistic): path-filtered jobs, sccache for cargo, reuse of main's wasm artifacts when no crate changed, browser matrix kept nightly (section 15).
- R2-m7 (five SaaS subprocessors): consolidated observability, alerting, on-call and synthetic probes into Grafana Cloud plus Sentry; the help desk is replaced by a support mailbox ingested into the console triage queue; the status page vendor receives no learner data; each remaining vendor is listed with its data classes (sections 4.15, 4.16, 14).
- R2-m8 (Diagnose step and cut arithmetic unclear): the seeded-error catalog and InjectedErrorSet schemas ship in step 2; the injector, grading path and content are one 5 ew item in the default cut list; the cut-list arithmetic is restated (24 ew deferred, 165 ew MVP, 189 ew full scope); proposed ADR amendment A3 (sections 2, 17, 20).
