# Architecture decisions

Decisions recorded by the synthesis (final, after refutation). Each is binding for implementation unless ADR 0001 or the user overrides it.

| id | decision | rationale |
|---|---|---|
| D01 | Job queue is pg-boss on the primary Postgres behind a Jobs interface; no Redis at MVP. | A submission row, its learning event and its grading job commit in one transaction, making zero-lost-submissions a database invariant; MVP load is two orders of magnitude below pg-boss's ceiling; the interface keeps BullMQ open. |
| D02 | The API is Next.js route handlers over a framework-agnostic packages/api-core, with a Hono mount as the escape hatch. | Halves auth, tracing and deploy plumbing for four engineers while keeping the handlers portable if route-handler streaming ever limits the API. |
| D03 | Authoritative solves run in bridle-runner, a warm per-slot Wasmtime process with a cwasm cache, fuel metering, epoch wall limits and 512 MB memory, a fresh Store per job. | Removes the 0.5-2 s Cranelift compile per job that the burst arithmetic omitted, keeps cross-tenant isolation per job, and gives a deterministic work meter for CI gates. |
| D04 | The live latency contract attaches to a live band (predicted flops <= 2e8, DOF <= 6,000, cases <= 24, combinations <= 60) and two committed reference scenes; Tier-M models above the band run in Run mode with progress (ADR amendment A1). | The 300 ms figure cannot be met at 12k DOF; predicted work from the symbolic analysis is the FE domain's own routing basis and is computed identically on both sides. |
| D05 | The engine carries a fresh-equivalence invariant: re-assemble from the canonical list every solve, reuse ordering only on an unchanged graph, reuse the factor only on byte-identical K; freshSolve at submit computes client_result_hash. | Floating-point addition is not associative, so incremental state would otherwise differ from the server's fresh solve by ulps and page constantly; the invariant makes exact result_match the normal outcome by construction. |
| D06 | Submissions include a canonical result_summary document (about 300 KB at Tier M) and result_match records which comparison ran (full hash or summary) with max_rel_diff. | A tolerance comparison needs the client's values; the summary keeps the bundle under 5 MB and provides the 'show both values' evidence for the R7 mid-offering upgrade case. |
| D07 | Results are hashed as a binary frame (JCS header plus int64 little-endian arrays plus per-member envelopes) and stored as a zstd generating set (per-case nodal displacements and reactions); derived results are regenerated under the pinned artifact. | JCS of a Tier-M result set is 30-80 MB and 1-3 s to serialize; the FE domain's own formulation is the int64 array; the generating set is about 0.6 MB at the cap and keeps storage inside COST-01. |
| D08 | Canonicalization adds per-field quanta (Cw, alpha, gradients, strain, damping), a schema walk test that fails on any numeric field without a quantum, and an error on counts >= 2^53; the solver consumes dequantize(canonicalize(model)) on both sides. | Without these the cache key is coarser than the solver input and a 2.5 percent change in E*alpha*dT could collide; the invariant makes model_hash identify exactly the analyzed model. |
| D09 | The engine promotion gate runs on a determinism corpus covering the sparse path (reference scenes, templates at S and M, ill-conditioned fixtures, nightly 1,000 random models) on five wasm hosts; performance regressions are gated on wasmtime fuel (5 percent) with weekly self-hosted laptop measurements as the R14 evidence. | The 25 closed-form problems only exercise the dense path, and wall-clock on shared CI runners varies 20-50 percent. |
| D10 | Op-log segments are posted every 30-60 s (flush on blur, hide, submit), stored as zstd bytea rows in daily Postgres partitions for open sessions, rolled up to content-addressed S3 objects every 15 minutes and at session end; no per-op rows; a blob_refs table reference-counts shared objects. | Per-op rows at 5-second cadence would be 150-500 inserts per second and S3 PUTs at that cadence cost $250-650 per month at the SCL-01 target; rollups cost about $4 and reference counting makes erasure safe. |
| D11 | Postgres runs on db.m7g.large Multi-AZ and the k6 deadline burst runs on the production instance class before the pilot. | The database is store, queue, outbox and SSE change source; a burstable class is sized for idle and surfaces credit exhaustion on the bill during deadline week. |
| D12 | SSE streams fan out from one LISTEN/NOTIFY connection per web task with 25 s keepalives, a 3,600 s ALB idle timeout, Last-Event-ID replay, a 5-stream cap per user and a polling fallback. | Polling Postgres per stream would add hundreds of RLS queries per second at a deadline and the default ALB timeout drops idle streams. |
| D13 | Judge latency and cost are measured on 50 golden grades (effort medium and high, concurrency 12) before any SLO, budget or burst figure is published; the harness pins the cheapest effort that holds its gates; effort is always set explicitly. | The 30 s call and $0.14 median were asserted; Opus 5.5 has no Priority Tier, a per-model rate pool and a default effort of medium, so nothing can be sized from list prices alone. |
| D14 | Summative judged stages run interactively (concurrency 8, 12 in windows); formative judged stages, regrades, calibration and the harness run through Message Batches. | Formative tasks promise deterministic results immediately and only an AI-provisional narrative, so the batch delay is acceptable, the cost halves and the interactive lane is reserved for summative work. |
| D15 | The planning cost basis is the cold task cache ($0.25 median, $0.50 p95 at effort high; $0.12 formative in batch); COST-02's $0.15 median is conditional on measured output; tenant budgets are sized from the measured p95 with a 1.5x margin; max_tokens is 16,000 with streaming. | Off-peak traffic cannot keep a 5-minute task-block cache warm, cache writes cost 1.25x or 2x, and budgets sized from an optimistic median would trip the 100 percent hard stop mid-term. |
| D16 | The published burst SLO is deterministic 100 percent within 10 min and judged 95 percent within 60 min pending measurement; the burst runbook's first action is deferring formative judged stages to Batches; the Opus 5.5 rate-limit tier is requested from measured needs. | At an assumed 60 s per call, 500 calls at concurrency 12 take about 42 minutes, so a 30-minute promise cannot be made before measurement. |
| D17 | Every provider call goes through packages/grader/judge-client with record/replay fixtures as its contract; a model-deprecation runbook declares judged criteria non-replayable after retirement and routes appeals to manual judging. | Model ids are not artifacts Bridle controls and retire on a 12-18 month cadence; the seam contains a second provider and the runbook makes appeals on retired models answerable. |
| D18 | MVP resistance checks are AISC 360-22 LRFD W-shapes only (D2, E3, F2 compact, G2, H1, B4.1, slenderness advisories); HSS, pipe, E4, F3, F6 and ASD ship as pack minors after the pilot; conformance is paper fixtures at MVP (ADR amendment A2). | The first pack is the code, not data; 20 ew at the cut scope is the honest estimate and the starter course needs only beams, trusses and W-section frames. |
| D19 | The workspace is delivered as parity-first core, 3D tools, then overlays, with instancing and BVH picking from day one; extruded sections, named views, radial arrays, multiple probes and the title block are v1.1. | A CAD-grade modeler plus a keyboard-only editor is 26 ew, not 13; the parity core is also the e2e, tutorial and author-mode surface and unblocks authoring early. |
| D20 | The plan is 165 engineer-weeks with the cut list applied by default (189 at full scope), a 0.7 focus factor, a contracted Rust/FE engineer for months 1-6, a spring-2028 pilot with production-ready and content-ready 2027-12-01, and a formative-only friendly alpha in summer 2027 (ADR amendment A4). | A fall-2027 production-ready date is unreachable at any credible estimate; the alpha validates the loop early and slips consume alpha scope before the pilot date. |
| D21 | Task, rubric and deliverable schemas freeze at month 3 with fixtures; a content pipeline milestone at month 6 runs deterministic-only grading on all templates with golden-submission capture; the content track has its own owner and the six-week buffer is counted backwards from the term. | Calibration needs the pipeline and MVP-01 needs 10 golden submissions per task before the pilot, so content authored against a moving schema would consume the buffer in rework. |
| D22 | A one-time launch budget ($80-160k non-headcount plus insurance annually) and a dated external-dependency calendar (counsel, AISC and ACI requests and SME agreements at M0; pentest booked by M4 for the October code freeze; insurance and pilot agreement by M9; WCAG, HECVAT Lite and DPIA at M11) are part of the plan. | Twenty-one of the licensing set's requirements are launch blockers with money and lead time an order of magnitude above the monthly cloud line, and none of them should land in the last step. |
| D23 | Deadline windows derive only from summative activities with >= 25 affected learners and are merged per tenant; capacity is scheduled from that calendar by the system entrypoint (audited as policy); transient dead letters auto-replay; single-admin break-glass rollback inside windows with next-day review; 0.75 FTE run allocation per pilot term. | Windows from every summative task would freeze deploys on roughly 40 percent of term days; scheduled capacity is deterministic and consistent with the no-autoscaler guardrail; the run load is real and must be budgeted. |
| D24 | Hidden reference sets are generated at activity release and at enrollment, cached by (task_version_id, seed), with on-demand generation only as a fallback; calibration auto-sizing is bounded with stated budgets. | Generating on first open queued hundreds of runner jobs at lab start and starved behind the grade lane; unbounded greedy sizing could take hours per task version. |
| D25 | Observability, alerting, on-call and synthetic probes consolidate on Grafana Cloud plus Sentry; the help desk is a support mailbox ingested into the console; the status page vendor receives no learner data. | Each SaaS subprocessor needs a DPA, a subprocessor-list entry and PII hygiene through every HECVAT; the paperwork, not the dollars, is the cost for four people. |
| D26 | Hosting is AWS us-east-2 (RDS, S3 with Object Lock, ECS Fargate, CloudFront, KMS, SES, Secrets Manager in OpenTofu); the backend is TypeScript end to end with Rust confined to the core and runner; the second pack is NSCP 2015. | Q1-Q3 answered: AWS maps onto FERPA and HECVAT asks and an EU tenant is a second workspace; a second service language would double every operational surface for four people; NSCP reuses the AISC resistance module and validates the pack split with the least new numerics. |
