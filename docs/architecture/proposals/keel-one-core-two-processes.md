# Proposal: Keel: one core, two processes

_Angle: Simplicity first for a 3-5 person team. Minimize the number of things that can be down at 2 a.m. before a deadline: one Rust core artifact that is the same bytes in the browser and on the server, one container image that runs as two processes (web and worker), Postgres as the only stateful service besides S3, managed everything, and an explicit list of what is deferred and where the seam for it already exists. Every binding resolution R1-R18 of ADR 0001 is honored; the one place the proposal narrows a user default (Redis queue) is justified below._

## Summary

Keel is a two-process monolith built around one Rust core. Everything that defines identity or numbers (canonicalization and hashing, validation, the FE solver, ASCE 7-22 scenario and load derivation, the AISC 360-22 checks library, the similarity fingerprint, the seed PRNG, answer-field queries) lives in one crate, bridle-core, compiled to one WebAssembly artifact; the browser runs that .wasm in a Web Worker for the live loop and the pre-submission self-check, and the grading worker runs the identical bytes under Node's built-in WebAssembly runtime, so engineArtifactHash is one digest and the R7 integrity check is exact resultHash equality by construction (the native build still exists, is pinned in the engine manifest with its own digest per R9, and runs the CI benchmark suite and the CLI harness). The product surface is one Next.js 15 application (UI plus /api/v1 route handlers, which is the Node API) and one worker process started from the same Docker image; both run on ECS Fargate in a single AWS region (R13). Postgres 16 is the only stateful service apart from S3: it holds every entity with row-level security tenancy, the append-only events table that is simultaneously the transactional outbox and the audit index, and the job queue (pg-boss), which lets a submission insert and its grading job be one transaction so the zero-lost-submissions invariant is structural rather than reconciled after the fact. Redis is deliberately absent at MVP and returns in v1.x only if team presence or co-editing needs pub/sub fan-out. S3 holds model revisions, result sets, submission bundles, op-log segments, attachments and artifacts, plus an Object Lock bucket for WORM audit copies. The AI stage is two Claude calls through the official TypeScript SDK: a claude-haiku-5-5 screen and one claude-opus-5-5 judge-plus-narrative call with structured outputs, adaptive thinking and a pinned effort, grounded only in the deterministic evidence digest and post-validated by a grounding validator; summative grades land in a 100% instructor review queue (R11) and formative tasks release deterministic results immediately with an AI-provisional narrative. Code packs are a data bundle plus a Rust trait implementation pinned by ArtifactRef in the activity pin set, so the second pack plugs in without touching the engine, grader or UI (R2). The MVP is roughly 125 engineer-weeks across 16 steps, runs on about $700 per month of infrastructure, and deliberately defers Redis, native-on-server grading, WebGPU, COOP/COEP threading, LTI and SAML, plates, iterative P-delta, Diagnose content, a second region and the marketplace, each behind a named seam.

## Data model

**Tenancy:** One Postgres database, one schema. Every tenant-scoped table carries tenant_id NOT NULL and an RLS policy USING (tenant_id = current_setting('app.tenant_id', true)::uuid); the application role has no BYPASSRLS; web sets SET LOCAL app.tenant_id at the start of every request transaction from the session's active membership, and the worker sets it from the job payload. Users are global rows with tenant membership via role_assignments; platform-only tables (artifacts, feature_flags, users) have no tenant_id and are gated by role. The operator console uses the bridle_ops role with a reason-required middleware and emits disclosure events for every education-record read. S3 keys are tenant-prefixed and served only by presigned URLs scoped by the API's authorization. tenant.region is reserved and fixed to 'us' (R13); an EU tenant in v1.x is a second OpenTofu workspace (separate RDS/S3/KMS in eu-central-1, inference_geo 'eu'), not a multi-region schema. Analytics actor ids are HMAC-SHA256 pseudonyms under a per-tenant KMS-wrapped key. CI runs the cross-tenant authorization suite (every route as every role across two tenants, zero unauthorized 2xx) and a presence test that fails if any tenant table lacks a policy.

**Storage:** Postgres holds rows and JSON up to roughly 64 KB (pins, definitions, criterion scores, indexes); S3 holds content-addressed blobs: canonical model revisions (gzip JSON, <= 5 MB at Tier M), result sets (JSON with Float64 arrays base64 plus the quantized canonical form for result_hash), GradeEvidence arrays, submission bundles (receipt + deliverables + pins), attachments (3 x 20 MB), required snapshots (PNG + view-state sidecar), op-log segments (<= 500 ops / 5 s, hash-chained), diagnostic bundles (<= 10 MB, 90 days), DSR exports, and artifacts (wasm <= 2 MB, pack bundles). Retention by class: learning records 5 years after offering end then pseudonymized; LLM prompts/responses 12 months encrypted at rest; process class 30 days; op-log segments 90 days unless promoted; audit >= 7 years in Object Lock; backups PITR 35 days plus weekly snapshots 1 year; deleted-user data purged 30 d primary / 90 d backups. Daily retention job reports counts per class and tenant.

## Structural model schema

Package packages/schema owns bridle-model@1.0.0 as JSON Schema 2020-12 (source of truth; TypeScript types generated by json-schema-to-typescript, Rust serde structs in bridle-core validated against the same golden corpus; no hand-maintained duplicates). Global conventions frozen in v1 before any code (R8, DM-09): right-handed, +Z up, gravity [0,0,-9.80665], 2D models live in the global XZ plane with Y = 0 and out-of-plane DOFs implicitly restrained (settings.mode: '3d' | '2d-xz'), SI base units for every stored quantity, display units only in a separate view-state document, member orientation = roll angle (rad) about local x (i->j) with an optional orientation vector, local axis convention documented once by the FE module and referenced. Shape follows the SIM-SCH-01 outline: {schemaVersion, id (mdl_), revision, settings{mode, gravity, tolerances{mergeNodes 0.001}}, materials[], sections[{kind: catalog|parametric|custom, catalog{db:'aisc-shapes-v16', label}, props{A, Iy, Iz, J, Cw, Sy, Sz, Zy, Zz, ry, rz, Asy, Asz}, dims{d, bf, tf, tw, h}}], nodes[{id, x, y, z, levelId?}], levels[], members[{id, type: frame|truss, nodeI, nodeJ, sectionId, materialId, orientation, releases{i, j}, offsets, timoshenko, design{Ky, Kz, Lb, Cb, bracedLateral, role}}], links[], supports[{nodeId, dof{tx..rz: fixed|free|{k}}, localAxes?}], loadCases[{id, type, selfWeight?, generator?{kind, params, provenance}}], loads[{caseId, kind: nodal|memberDistributed|memberPoint|thermal|areaPanel|settlement, target, axes, projected, values}], panels[{polygon, distribution:'oneWay', spanDir}], combinations[{code:'ASCE7-22'|'custom', terms, envelope}], analyses[{type:'linearStatic'}], groups[], meta{authorId, taskId?, parentModelId?, ownerType, ownerId}}. Shells, regions, constraints and modal/buckling/pDelta analysis types are present in the schema as reserved, empty-by-default collections and enum values (R3, R4) so v1.x adds them without a canon bump. Every element has a client-generated, never-reused id (UUIDv7-based, typed prefix n_/m_/s_/l_/c_), all references are by id, ordered collections carry fractional order keys and deletes leave tombstones only in the op log (GAP6-03). Canonicalization canon/1 is implemented once in bridle-core (DM-10): project onto schema-flagged semantic fields (drop labels, colours, camera, selection, groups-as-display, comments, timestamps, authorship, display units), materialize defaults, quantize each number to an integer count of its dimension's quantum (length 1e-6 m, angle 1e-6 rad, force 1e-3 N, moment 1e-3 N m, line load 1e-3 N/m, stress/modulus 1 Pa, area 1e-10 m2, I/J 1e-14 m4, section modulus 1e-12 m3, density 1e-3 kg/m3, temperature 1e-3 K, spring 1e-3 N/m and N m/rad, mass 1e-6 kg, dimensionless 1e-6; round-half-even, -0 -> 0, non-finite is an error), NFC strings, lowercase snake_case enums, omit absent optionals, arrays sorted by id, header {"schema":"bridle-schema@1.0.0","canon":1,"kind":"model"}, RFC 8785 JCS, UTF-8, SHA-256 -> model_hash 'sha256:<hex>'. The same function produces result (quanta: displacement 1e-9 m, rotation 1e-9 rad, force 1e-3 N, moment 1e-3 N m, stress 1 Pa, utilization 1e-6), scenario, evidence, submission and grade canonical forms. Op protocol (SIM-SCH-02 + GAP6-02): ops are {documentId, seq (server-assigned, gapless), clientOpId, actorId, actorRole, onBehalfOf?, sessionId, origin (user|undo|redo|import|restore|system|migration), baseSeq, lockEpoch, gestureId, undoOfSeq?, type (create|set|delete|batch), target{elementId, path}, before, after, clientTs, serverTs}; invertible; replaying the log reproduces model_hash (CI test). Hashes: model_hash on every revision and submission; result_hash on every result set; scenario_hash; evidence_hash; submission_hash and grade_hash over the canonical pin records; engineArtifactHash = sha256 of the .wasm bytes. Versioning: bridle-schema minor versions are additive and readable by N-1 consumers for 90 days; any change to semantic fields, quanta, ordering or header bumps canon and never rewrites stored hashes (DM-24); migrations are tested from every prior fixture version. Golden corpus: >= 50 vectors (input -> canonical bytes -> hash) run in Rust native, Node (wasm) and Playwright Chromium/Firefox/WebKit; any byte difference fails CI. Performance target: 5,000-node/10,000-member model canonicalized and hashed in <= 200 ms in wasm, <= 50 ms native.

## Solver and checks core

Language and layout: one Rust crate, crates/bridle-core, with modules model, canon, validate, fem (elements, assembly, ordering, factorization, recovery), combos, results, pack (CodePack trait) + pack_us, checks_aisc, serviceability, fingerprint, seed, queries, evidence; plus crates/bridle-cli (native binary: benchmarks, golden corpus, pack conformance, harness runner, OpenSees cross-check driver). Build targets: (1) wasm32-unknown-unknown via wasm-bindgen with +simd128, no threads, no relaxed SIMD, opt-level 3 + wasm-opt, target <= 1.5 MB raw / <= 500 KB gzipped, instantiated in < 300 ms; this artifact is loaded by the browser worker AND executed by the grading worker under Node's WebAssembly runtime, so engineArtifactHash is one sha256 for both sides and result_match is 'exact' by construction (R7, C7); (2) host native via cargo (cdylib through napi-rs available as the alternative EngineRunner 'native'), used for cargo test, criterion benchmarks, the nightly verification suite, the CLI harness and reserved for v1.x Tier-L server analyses; its digest and numeric_profile are recorded in the engine manifest alongside the wasm digest (R9, DM-04), and the worker runner is a one-line config switch (ENGINE_RUNNER=wasm-node|native) with result_match falling back to tolerance comparison per DM-11 if native is ever made authoritative. Determinism recipe (SIM-DET-01): sorted entity ids drive assembly order (BTreeMap and sorted Vec only), single-threaded kernel, libm crate for sin/cos/sqrt on all targets, no FMA (Rust default, no fast-math), no clocks or randomness in numerics, fixed sign conventions, NaN/Inf never leave the crate; CI asserts identical result_hash for every benchmark across wasm-in-Node, wasm-in-Chromium/Firefox/WebKit and macOS/Linux native (native must match wasm bit-for-bit or the engine release is blocked; if a platform ever diverges the wasm hash is the reference). Numerics: AMD ordering, simplicial LDLT (symmetric indefinite safe for releases and springs), multiple right-hand sides (all cases in one factorization, N <= 20 cases < 1.3x one case), one step of iterative refinement with residual check (warn > 1e-8), dense path < 500 DOF, factorization reuse for load-only edits (< 10 ms) and symbolic reuse for geometry-only edits, pivot threshold 1e-12 x max diagonal for mechanism detection with DOF localization, condition estimate warning above 1e12. Elements and loads at MVP: 12-DOF frame with releases (static condensation), rigid offsets, optional Timoshenko; truss with automatic rotational DOF removal; spring/link; per-DOF supports with inclined axes and prescribed settlement; nodal, distributed (uniform/trapezoidal/partial/projected), member point, self-weight, thermal (uniform and gradient), one-way panel loads; 2D XZ mode. Out of MVP (R3, R4): shells, regions, diaphragm constraints, modal, buckling, iterative P-delta, moving loads. Stability at MVP (R4): B1/B2 amplification from first-order results, notional loads as load cases, ASCE 7-22 12.8.7 theta, slenderness advisories, mechanism detection, Delta2nd/Delta1st <= 1.5 validity rule for T5 tasks. Checks library: AISC 360-22 LRFD and ASD for W, HSS and pipe (D2 yield/rupture with U, E3/E4 with Lc/r, F2 compact with Lp/Lr/Cb, F3 noncompact flange, F6 weak axis, F7 HSS, G2 with Cv1, H1-1a/b, Table B4.1 classification, Lc/r <= 200 and L/r <= 300 advisories), serviceability (IBC 2024 Table 1604.3 defaults, wind drift H/400 under 0.42W, seismic drift Table 12.12-1), each finding carrying pack ref, clause id, equation id, substituted values with units, demand, capacity, ratio, governing combination and station; non-steel materials get generic elastic stress and deflection checks. Verification: ~25 closed-form engine benchmarks (cantilever, SS/fixed/propped beams, settlement, thermal bar, portal sway, Warren truss, beam on springs, releases, offsets, inclined roller, 2D vs 3D equivalence) at 1e-6 relative, >= 30 AISC Design Examples v16.0 capacity reproductions within 2% (SME-authored inputs, cited by example id only per LIC-03), >= 15 US-pack consistency-rule fixtures, combination-set golden lists, and an offline OpenSees cross-check of 5-10 problems (research use only, never shipped); fast subset <= 3 min on every PR, full suite nightly with a +/-15% timing gate; verification report generated per release and signed into the pack verification record. Artifact versioning: semver (numerics-affecting change = minor bump + benchmark diff report), content-addressed, retained >= 3 years, registry states candidate -> verified -> default -> deprecated -> revoked, promotion requires the cross-platform hash gate and a second platform admin. Model-size tiers (R14): S <= 200 members (~<= 1,200 DOF) with solve+render <= 100 ms p95, M <= 2,000 members (~<= 12,000 DOF) with <= 300 ms p95 on the reference laptop (4-core 2020 laptop, Iris Xe / M1, 8 GB); no L tier at MVP; authors set a per-task hard cap (members and DOF) that bridle-core.limits() enforces identically in the workspace (edit refused with a message), at submit (422) and in the worker (job rejected before queueing). Server deterministic stage budget: <= 10 s p95 compute for M-tier models with <= 20 combinations (wasm in Node single-thread; a 3.2k-DOF frame solves in ~50 ms, M-tier worst case ~1-2 s), well inside the 60 s stage SLO.

## Live loop

Path: user edit -> command bus -> zustand document store applies the invertible op (undo stack) and appends it to the local op log -> IndexedDB autosave (<= 2 s) -> Engine Worker.applyOps(ops, seq) (debounced 30 ms for typed edits, 100 ms for gizmo drags; sequence-numbered; superseded requests cancelled, stale responses dropped) -> bridle-core validates (< 20 ms, issues with stable ids and fix actions) -> solve (factorization reuse when only loads changed; symbolic reuse when only geometry changed) -> result recovery -> checks (same checks module as the server: utilization per member with governing clause/combination/station, deflection ratios, drift) -> transferable Float64Array buffers + JSON index posted back -> main thread updates GPU buffers in place (deformed shape with Hermite interpolation, N/V/M ribbons, utilization colour map, reaction arrows, probes, result tables) and clears the stale badge. Latency budget per tier on the reference laptop: S (<= 200 members) worker solve <= 50 ms p50 + checks <= 20 ms + transfer/render <= 30 ms = <= 100 ms p95 commit-to-fresh; M (<= 2,000 members) <= 300 ms p95 with checks debounced to the trailing edge of drags; load-only edits < 10 ms; validation on every edit < 20 ms; UI thread never blocked > 16 ms by engine work and > 50 ms by anything (Long Tasks assertion in e2e); case/combination switching repaints cached results in < 100 ms without re-solving. Self-check ('Check my design'): the worker runs selfCheck(taskDefinition, scenarioInstance) which executes the identical deterministic rule stage the server runs (validation, scenario consistency, load and combination diff against the pack-generated set, constraint evaluation, code checks, deliverable completeness) and returns GradeEvidence records; the client and server evidence are hash-equal for the same model and artifact (CI fixture test), filtered to the task's assistance profile disclosure level (0-4) before display, counted against the per-task self-check cap enforced server-side. Fallback to the server: there is none for live mode at MVP by design, because every MVP task is capped at Tier M and the browser is the only interactive solver; models above the live tier switch to explicit Run mode with a progress indicator inside the worker (still in-browser), and the server runner is used only for authoritative grading, author calibration and test-submits (POST /api/v1/tasks/{id}/versions/{v}/test-submit runs the full pipeline in dry-run). The v1.x seam for an interactive server solve (Tier L) is the existing analyze queue plus the EngineRunner 'native' mode; the workspace already carries the job-status polling component used for calibration. Offline tolerance: edits, live analysis and self-check continue through API outages; draft segments queue in IndexedDB and reconcile on reconnect (last-writer-wins per document with a restore-previous option); the LLM is never on the live path. Exam mode: the checks artifact, hints and self-check endpoints are withheld server-side (403 exam_mode) and the worker is instantiated without the checks data bundle, so 'off' is enforced, not hidden.

## Code packs

Structure: a code pack is (a) a Rust module implementing the CodePack trait in bridle-core and (b) an immutable data bundle under packs/<pack-id>/ {manifest.json (id, semver, content sha256, attribution text, legal_basis, licensing register ids, supersedes), tables/*.json (coefficients keyed by clause id: ASCE 7-22 Tables 1.5-2, 4.3-1, 4.7-1, 7.3-1/2, 11.4-1/2, 11.6-1/2, 12.2-1 subset, 12.8-1/2, 12.12-1, 26.6-1, 26.10-1 derivation constants; AISC Table B4.1 limits and resistance factors; serviceability presets), combinations/*.json (LRFD 2.3.1 + 2.3.6, ASD 2.4.1 + seismic templates with direction/sign expansion rules), systems.json (SMF/IMF/OMF, SCBF/OCBF, BRBF with R, Omega0, Cd, height and SDC permissions), rules/consistency.json (>= 15 data-driven scenario-structure rules with id, condition, message, severity), clauses/registry.json (~50 clause ids with code, edition, clause number, short Bridle title, Bridle-authored explanation, typical fixes, official link; zero verbatim text), equivalences.json (clause notation variants), verification-record.json + .sig (SME record bound to the bundle hash), CHANGELOG.md (errata with S1/S2/S3)}. Trait (stages actions -> combinations -> effects -> resistances -> verifications -> findings): derive_loads(scenario, model, options) -> {cases[], derived_params (Kz, qz, Cs, T, k, pf...)} with every derived load referencing its scenario parameters; combinations(cases, method: LRFD|ASD, service: bool) -> Combos[] with names and factors; required_set_diff(learner_combos, generated) -> load_combination evidence; check_member(member, section, material, design_attrs, demands_per_combo) -> Finding[] (limit state id, demand, capacity, ratio, governing combo/station, clause id, equation id, substituted values); serviceability_limits(task_overrides) -> limits; consistency_rules(scenario, model) -> Finding[]; clause(id) -> ClauseRef; limit_state_catalog() for the Check archetype; cost_index(sections) via the cost model artifact. Loading: the pack module is compiled into bridle-core (feature flag per pack so an artifact can be built with one or several packs), the data bundle is fetched by digest (browser: from CloudFront with immutable caching; worker: from S3) and passed to loadModel as bytes; bridle-core hashes the bytes and refuses a mismatch with the pinned codepack ref. Versioning: codepack:<id>@MAJOR.MINOR.PATCH#sha256 where MAJOR = edition change (ASCE 7-28, ACI 318-25), MINOR = new checks or coverage, PATCH = errata; tasks pin the pack ref in the activity pin set; a published task version never changes pins automatically; a pack upgrade is an explicit pins-only task version with the VP-03 in-flight choice and regrade policy. Publish gate (CI, tools/ci/pack-publish-gate): licensing register entry approved and not past review_due (legal/licensing-register.yaml), no-verbatim similarity scan where permitted or two-reviewer attestation ids present, >= 1 benchmark per check id passing within 0.5%, combination golden lists, consistency-rule fixtures, SME verification record signed over the bundle hash, disclaimer tests. Clause traceability: every GradeEvidence record carries code_ref {code, edition, clause, title, library_id} and computed_by {stage, component_version}; the grounding validator rejects any clause id in LLM output that is not in the registry and the digest; the feedback UI and generated help pages (help/clause/<pack>/<clause>) render the Bridle explanation plus the learner's own demand/capacity values with a link-out to the official standard; API responses carry code_pack_version and verification_status. MVP pack: us-asce7-22-aisc360-22 v1.0.0 (steel only, R1; 'simplified' scenario fidelity, R5); ACI 318-19 reduced scope ships as a pack increment v1.1 behind the LIC-05 counsel gate with its data in a separate bundle so steel grading is unaffected if ACI consent is delayed. How the second pack plugs in (v1.x, R2, Q1): add crates/bridle-core/src/pack_nscp2015 (or pack_ec_gen1 with a UK NA overlay object) implementing the same trait, a packs/<id>/ bundle, and its conformance suite (>= 10 published seismic/wind examples for NSCP, SCI P362/P363 for EC3, combination golden lists, clause registry, SME record, LIC-08 register entries); no change to the engine, the evidence schema, the grader, the rubric or the workspace beyond the pack picker and unit defaults; the stage interface was chosen so NSCP's UBC-97-lineage seismic (Ca/Cv/Na/Nv) and EN 1990's partial-factor combinations both fit, and the NSCP pack reuses the US member-check module with its own coefficient tables.

## Grading pipeline

One pg-boss job per (submission_id, grader_version) with persisted stage checkpoints in grading_jobs; stages are pure functions in packages/grader and are individually re-runnable from the operator console. S0 Intake (deterministic): validate the bundle against the deliverable schemas, re-derive model_hash from the stored revision (already enforced at submit with 422), check size/rate limits (bundle <= 5 MB, members/DOF <= task cap, memo <= 1,500 words default, 3 attachments x 20 MB), scrub PII from memo text (names, emails, student ids, institution names; scrub log stored), pin the activity pin set. S1 Re-analysis (deterministic): load the pinned engine .wasm by digest into the worker's warm pool, instantiate the stored scenario instance, derive loads and the full required combination set through the pinned pack, solve all combinations, write the result set to S3 (cache hit if (model_hash, scenario_hash, engine_ref, numeric_profile, options_hash) exists), compute result_hash and result_match against client_result_hash (exact when engine refs match, within_tolerance 1e-6 relative otherwise, mismatch -> integrity flag and review); analysis failures (mechanism, singular, cap exceeded) become analysis_error evidence with severity critical so the job completes. S2 Rules (deterministic): validation, scenario consistency, load/combination diff, task constraints, code checks, serviceability, stability (B1/B2, theta), efficiency and cost versus the per-seed benchmark (author references plus the greedy auto-sized reference generated at calibration, R10), wrong-instance check (bound quantities versus the learner's own instance), archetype deliverable grading (Analyze three-way comparison with unit-error fingerprints; Check key matching with 0.50/0.15/0.15/0.10/0.10 entry credit, false-positive and unsafe-approval penalties and the 75% cap; Diagnose detection/correction/collateral), memo-model coherence check; output GradeEvidence[] v1.0 ({evidence_id 'EV-<type>-NNNN', criterion_ids, check_type, subject, status, severity, metric{value, unit, limit, comparator, margin_pct}, governing, values, code_ref, message_key, visual, computed_by}) stored in S3 with evidence_hash, plus the deterministic EvidenceDigest (all fail/warn up to a cap, top-N governing per check type, all constraint/integrity/error/efficiency records, summary stats; sorted keys, no timestamps or identity; <= 12k tokens verified by count_tokens). Deterministic evidence is visible to the learner within 15 s and the stage is budgeted at <= 60 s p95 (3x hard ceiling then stuck alert). S3 LLM (non-deterministic, pinned, cached; skipped for deterministic-only tasks, the sandbox tenant and under the kill switch): (a) screen call on claude-haiku-5-5 with structured output {injection, pii_residue, off_topic, language}; (b) one judge call on claude-opus-5-5 returning JudgeOutput = {criteria: [{criterion_id enum, level enum 0-3, evidence_refs[], rationale, memo_claims[{claim, verdict supported|unsupported|contradicted, evidence_refs[]}], confidence enum, flags enum[]}], narrative: {summary, strengths[], issues[{evidence_id, clause_library_id?, problem, action, priority}], next_steps[]}} via output_config.format (additionalProperties false, enums only; no field can touch an auto criterion), thinking {type: adaptive}, output_config.effort pinned per route (opus route 'high' at MVP; re-tuned on the golden set with the cheapest level holding QWK >= 0.75), max_tokens 16,000 (streaming, finalMessage()), no server-side fallbacks, response.model asserted, inference_geo recorded; prompt layout: system block 1 = grader charter and schema semantics (>= 1,500 tokens, cache_control ttl 1h, shared by every task), system block 2 = task block (judged criteria with level descriptors, clause explanations present in this task, scenario summary; cache_control 5 min, which stays warm during deadline bursts), user turn = evidence digest JSON + memo inside explicit untrusted-data delimiters + instruction; (c) grounding validator: every evidence_ref exists, every numeric literal in rationale/narrative matches a digest value (<= 3 significant figures after unit normalization) or the allow-list, every clause id exists in the pack registry and the digest, 'contradicted' requires refs; on failure append one role:system correction message (cache-preserving) and regenerate once; second failure -> template feedback from message_keys + flag validator_fallback. Judge results are cached in Postgres keyed by sha256(prompt bytes + model id + effort + schema digest) so a regrade with identical pins returns identical judged levels. Refusal (stop_reason refusal), truncation, 429/5xx/529 after jittered retries -> judged criteria pending/needs_review, never 0, no failed job (PIPE-01). Budget: at most 3 model calls per grade (screen + judge + one regeneration), input <= 25k tokens, cost telemetry per call rolled into per-task and per-tenant counters against the monthly budget with a global cap and the kill switch. S4 Aggregation (deterministic, pure): total = sum(weight x score / 100) with gates in order fail-task then caps (Critical -> 50%, Major strength/loads -> 75%, unsafe approval -> 75%, instability/constraint/integrity caps) then rounding; confidence = 0.35 judge_conf + 0.20 evidence_completeness + 0.15 (1 - validator_retries/2) + 0.15 min(1, |total - threshold|/10) + 0.15 memo_signal; flags when confidence < 0.7, |total - pass| <= 3, any critical gate, injection/contradiction/possible_copy, refusal or validator fallback; recomputed from stored rows on every display. S5 Routing and review: summative (credit-bearing) grades always enter status in_review for 100% instructor/TA review (R11) ordered by flag severity, confidence and age with bulk-accept only for unflagged grades above the tenant threshold; formative tasks release deterministic criteria immediately and show the narrative labeled 'AI-generated, pending instructor review'; instructors override per criterion or adjudicate per entry with a mandatory reason, each producing grade_version n+1 (source instructor, originals retained for calibration); release is atomic per activity and emits bridle.aig.grade.released consumed by gradebook, notifications and mastery projections. Reproducibility: every grade version stores the DM-06 pin set including judge_invocations; the composite grader_version {engine, checks, codepack, clauses, scengen, rubric, prompt, judge_schema, routes{screen: claude-haiku-5-5, judge: claude-opus-5-5 + effort}, validator, aggregator} is frozen per published task version (R17); regrades are new versions with a reason and only the re-pinnable fields may change; deterministic criteria are always recomputed, judged criteria re-invoked only for judge_rerun/pack_upgrade/rubric_fix/appeal/calibration and otherwise carried. Harness and calibration: bridle-grader eval runs golden fixtures per template (oracle >= 95, null = 0, two flaws, three memo variants, injection twins) with R = 3 repeats through Message Batches (50% off) and gates grader promotion on exact-level agreement >= 85%, within-one-level >= 97%, QWK >= 0.80 (0.75 at first pilot), flip rate <= 2%, injection pass >= 99%, cost per grade within budget; author calibration runs the same pipeline in dry-run over references and 20 sampled seeds before publish. Latency targets: deterministic evidence <= 15 s visible, deterministic stage <= 60 s p95, LLM stage <= 60 s p95 (<= 3 min p95 end to end at normal load, <= 20 min p95 under the 500-in-5-minutes burst), review-queue status refresh <= 5 s.

## API and contracts

One REST surface under /api/v1 served by Next.js route handlers, defined with zod and exported as OpenAPI 3.1 (CI fails on a breaking change without a version bump; packages/api-client is generated from it and used by the web UI, the CLI harness and later LTI). Conventions: JSON only; ids are typed-prefix UUIDv7 strings; timestamps RFC 3339 UTC with the offering timezone id carried separately; problem+json (RFC 9457) errors with stable codes (exam_mode, tenant_read_only, model_hash_mismatch, cap_exceeded, reveal_not_allowed); Idempotency-Key header required on POST /submissions, /grading-jobs/*, /regrades; cursor pagination; every response envelope carries disclaimer {code:'EDU_ONLY_V1'}, code_pack_version where relevant and verification_status, plus header X-Bridle-Disclaimer; rate limits 600 req/min/user, 120/min unauthenticated IP, auth 10/min/IP, submissions 10 per task default and 30 grading jobs/hour/learner, uploads 20/hour <= 25 MB, with 429 + Retry-After. ## Jobs and queues

Queue technology: pg-boss v10 on the primary Postgres (SKIP LOCKED, priorities, retries with exponential backoff, delayed jobs, cron, archival), chosen over the Redis default because it removes a managed service and, more importantly, makes enqueue transactional with the state change: POST /submissions inserts the submission row, appends the learning event and enqueues the grade job in one transaction, which makes 'every submission version has exactly one grading job' a database fact that the 15-minute reconciliation merely verifies. Throughput ceiling (low thousands of jobs/s) is two orders of magnitude above MVP load (<= 300 analyses/min, <= 1,000 grades/hour); polling interval set to 500 ms. Queues and lanes: grade (priority 10; submission grading S0-S5; per-tenant concurrency cap 50 and per-user cap 2 implemented as a tenant_slots counter row with advisory locks, over-cap jobs are re-delayed 5 s), analyze (priority 7; author calibration, test-submit, hidden-set generation at assignment time; standard limits 2,000 members, 50 cases, 200 combos, 60 s wall time), llm (priority 8; judge/screen calls; global concurrency 8 = provider rate budget; adaptive backoff on 429/529; paused by the kill switch or a tenant budget breach, jobs then complete deterministic-only and leave a pending-judged marker for backfill), batch (priority 3; regrades, bulk re-pin, calibration seeds, harness, nightly similarity, replay; capped at 25% of worker slots so it never starves grading; Message Batches used for LLM work here), system (priority 5; outbox relay to projections and notifications, email send, reconciliation every 15 min, retention daily at 03:00 tenant-local, deadline-window recompute nightly, WORM audit copy hourly, LLM backfill oldest-first at concurrency 4, artifact warmup). Worker sizing: 2 Fargate tasks x 2 vCPU/4 GB, each with processor concurrency grade 4, analyze 2, llm 8, batch 2, system 2; an operator control sets the ECS desired count to 4 during deadline windows (fixed pool, no autoscaler at MVP). Burst math (500 submissions in 5 minutes): deterministic stage ~1.5 s each at Tier M -> 500 x 1.5 s / 8 slots ~ 95 s; judge calls ~30 s each at concurrency 8 -> ~31 min for all, with deterministic results visible within minutes, inside the 'checks 100% within 10 min, AI 95% within 30 min' target. Retries and failure: infrastructure errors retry 3x with jittered exponential backoff (max 5 min); typed solver/model errors never retry; a job exceeding its stage budget (deterministic 60 s, judge 5 min, each with a 3x hard ceiling) is marked stuck and alerts within 10 min; exhausted jobs move to dead_letters with a reason class (solver_error|model_validation_error|llm_error|infrastructure|unknown) and the full replay payload, alert after 15 min, and are replayed or discarded with reason from the console. Idempotency: unique (submission_id, grader_version) on grading_jobs; re-running a job that already has a grade creates a new grade version and never a duplicate. Reconciliation invariant (every 15 min): for each submission version exactly one active or terminal job; review/released implies a stored grade version; failed implies a dead-letter entry; cancelled implies an audited reason; violations page on-call, auto-recreate the job preserving the original submit timestamp, and increment the lost-work counter shown on the exit-criteria dashboard. Op-log ingestion is not a job: segments are written synchronously by the API (<= 1 per 5 s per session). Seam: the Jobs interface hides pg-boss; moving the llm or grade queues to BullMQ/Redis in v1.x is a new implementation of the same interface plus an ElastiCache resource.

## Security and tenancy

Baseline: OWASP ASVS 5.0 L1 complete plus the L2 controls for authentication, access control and data protection (ADR guardrail), tracked in docs/security/asvs-checklist.md; third-party pentest before the first institutional pilot; security.txt and a 90-day disclosure policy; HECVAT Lite before the first contract. Authentication (R12): Auth.js v5 database sessions (httpOnly, Secure, SameSite=Lax cookies; idle 12 h learners / 2 h admins; absolute 30 days; revoke-all effective within 60 s); passwords argon2id, min 12 chars, breached-password check, no composition rules, progressive delay after 5 failures and 15-min lock after 10 per account+IP; Google and Microsoft OIDC with linking only by matching verified email; TOTP or passkey MFA mandatory for instructor, author, institution_admin and platform_admin with no bypass path; operator console additionally requires an MFA challenge within 12 h and an optional IP allowlist. Authorization: permission matrix as data with one authorize(document|resource, caller) function, section scoping for TAs, server-side enforcement on every route, plus Postgres RLS as the second layer; CI runs the two-tenant authorization suite and the RLS presence test as release blockers. Data protection: TLS 1.2+ everywhere, SSE-KMS on S3 and RDS encryption with keys separate from backups, LLM prompt/response logs encrypted at rest with 12-month retention and access logging, PII minimization toward the model (pseudonymous submission ids only, memo scrub, automated test asserting zero PII patterns in assembled prompts on every build), no training on API data (provider terms recorded in the register), inference_geo recorded per call. Grader hardening: learner text only in the user turn inside delimiters, haiku pre-screen, structured outputs with no auto-score field, grounding validator, clause-id validation, hard caps from deterministic gates that LLM output cannot raise, no tools and no network for the judge, injection attempts routed to the integrity queue with neutral learner messaging; red-team suite with a 99% identical-score gate. Web security: nonce-based CSP, HSTS, SRI on CDN assets, no COOP/COEP at MVP (single-threaded wasm; decision deferred to the LTI design per the guardrail), uploads via presigned PUT with type/size limits and virus scan (ClamAV in the worker). Integrity and audit: submissions content-addressed and immutable, grades append-only, audit events written synchronously in the mutating transaction, hourly WORM copies, FERPA disclosure events for every staff/operator read of an education record, impersonation only with a learner consent token, reason, time box (60 min default, 4 h max), denylist and learner summary email. Supply chain and secrets: secrets only in AWS Secrets Manager injected into ECS task definitions, gitleaks pre-commit and CI, Dependabot and cargo-audit, CycloneDX SBOM per release, license allowlist forbidding copyleft in the client bundle, images pinned by digest and rebuilt weekly, DB and LLM credentials rotated <= 90 days with a tested runbook. Abuse and cost controls: per-user/IP/tenant rate limits, per-task submission limits, model-size caps checked before enqueue, per-tenant monthly LLM budget with 80% alert and 100% pause, global kill switch (< 60 s), cost guard pausing server analysis above 150% of a tenant's daily budget. Privacy: FERPA school-official DPA template, directory data minimized, self-service DSR export within 72 h and erasure within 30 d primary / 90 d backups with grade pseudonymization, DPIA before launch, under-18 only through institution-managed accounts, learner-owned content with purpose-bound licenses and consent records for exemplar/calibration reuse.

## Observability

Structured JSON logs (pino) from web and worker with mandatory fields trace_id, span_id, tenant_id, actor_id (opaque), job_id, task_version_id, engine_ref, model_hash, grader_version, request_id; a CI redaction test proves no emails, names or memo text reach logs; retention 30 days in CloudWatch, audit events 7 years in Object Lock. Tracing: OpenTelemetry Node SDK with W3C traceparent propagated from browser fetch through API, pg-boss job payloads (traceparent stored on the job), the wasm runner and the Anthropic SDK (request/response ids as span attributes); 100% sampling for jobs, 10% for HTTP; exported to Grafana Cloud Tempo. Metrics (prom-client, scraped by a Grafana Agent sidecar into Mimir): RED per route; queue depth, oldest-job age and wait p95 per queue and tenant; job duration per stage and tier; solver failure rate by reason; wasm instantiate time; result_match distribution; LLM latency, tokens, cost per grade, cache_read share, 429/529 rate, refusal rate, validator retry and fallback rate; review-queue age and override rate; reconciliation violations and the lost-work counter; cost per server analysis and per grade; browser RUM for LCP/INP/CLS and workspace timings (solve ms by tier, frame time, context loss) sent via a tiny /api/v1/telemetry endpoint and the analytics event class. Error tracking: Sentry for the web app with source maps and release tags, console_error_panic_hook in the wasm build reporting structured panics, worker exceptions with job and tenant context; new error signatures triaged within 1 business day. SLO dashboards: availability (synthetic probes every 60 s from two regions against /healthz, the login page and a workspace load; target 99.5% monthly per the guardrail), analysis latency per tier, grading turnaround (deterministic <= 60 s p95, AI <= 3 min p95), LLM cost and cache share, exit-criteria dashboard (activation, time-to-first-analysis, completion, agreement, override rate, lost-work counter). ## Answers to open questions

Q1 Launch geography and second pack: keep the default of a US pilot first (US pack only, R2). Recommend committing now that the second pack is NSCP 2015 (7th ed.) rather than Eurocode, for three reasons: the structural brief names the Philippines as a founding-team market, NSCP reuses the US member-check module with its own coefficient tables (UBC-97-lineage seismic is a new load generator but not a new check philosophy), and it validates the CodePack trait with the least new numerical work; Eurocode first-generation with the UK National Annex becomes the third pack and additionally requires the EU database-right determination. Either way the second pack does not start until the MVP exit criteria are met and the LIC-08 register entries are approved; the trait interface is frozen at MVP with NSCP seismic and EN 1990 combination enumerations as conformance tests so neither pack forces an interface change. Q2 Backend language: TypeScript end to end (web, API, worker, grader orchestration, CLI) with Rust confined to the shared core; no Python service. A second service language would add a deploy unit, a second set of schema bindings, a second observability stack and a second on-call skill set for a 3-5 person team; everything the grading and solver services need (Anthropic SDK, zod/OpenAPI, pg-boss, S3, the wasm runtime) exists in Node. Python appears only as an offline tool (OpenSees cross-check scripts and notebook analysis of harness results), never in a request or job path. Q3 Hosting: AWS, single region us-east-2 (Ohio), with RDS PostgreSQL 16 (managed Postgres), S3 with Object Lock (object storage and WORM audit), ECS Fargate for the two services, CloudFront for artifacts, KMS, SES and Secrets Manager, all in OpenTofu. Chosen because S3 Object Lock, KMS envelope keys and RDS PITR map one-to-one onto the FERPA/HECVAT asks, the pilot institutions' security questionnaires know AWS, and an EU tenant later is a second OpenTofu workspace in eu-central-1 with inference_geo 'eu'. The one narrowing of the user defaults is that Redis is not provisioned at MVP (pg-boss in Postgres replaces the Redis-backed queue) because it removes a managed service and makes submission-plus-job enqueue transactional; the Jobs interface keeps the Redis path open for v1.x.

## Trade-offs

Pros:
- Two deployable processes from one image and one language outside the core: a 3-5 person team can hold the whole system in their heads and debug any job end to end from one trace.
- One wasm artifact executes on both sides, so the learner's self-check and the authoritative grade are provably the same computation (exact resultHash equality), which eliminates a whole class of grade disputes and the numeric-tolerance machinery between client and server.
- Postgres as the only stateful service: transactional enqueue makes the zero-lost-submissions exit criterion a database invariant; no Redis to run, patch, size or fail over; the outbox, audit index and queue share one backup and one restore drill.
- Typed contracts from one JSON Schema source consumed by TypeScript and Rust with a golden corpus that runs in five runtimes, so schema drift is caught in CI rather than in a regrade.
- Deterministic-first grading with a bounded two-call LLM stage keeps per-grade cost around $0.13 on the Opus route and makes an LLM outage a degradation (judged criteria pending) rather than an incident.
- Code packs as data plus a trait give R2 its second-pack seam without any engine or grader change, and the publish gate turns licensing and SME verification into CI facts.
- Managed AWS primitives (RDS PITR, S3 Object Lock, KMS, SES) cover the compliance asks (FERPA audit WORM, backups, encryption) without building anything.
- Baseline infrastructure about $700 per month, inside the $1,000 guardrail, with all variable cost (LLM tokens, server analysis seconds) metered per tenant from day one.

Cons:
- Next.js route handlers are a thinner API framework than a dedicated server: long-lived connections (presence, co-editing, live job streams) need a separate process or managed WebSocket service in v1.x; MVP polls instead.
- pg-boss adds queue load to the primary database and has ~500 ms pickup latency; it is far from its limits at MVP but becomes the first thing to move to Redis if Tier-L interactive solves or team fan-out arrive.
- Running the wasm artifact in Node for grading is slower than native (single-thread, ~1.5-3 GFLOP/s); acceptable only because every MVP task is capped at Tier M, and the native runner must be kept green in CI so the switch stays one config line.
- Auth.js plus hand-written TOTP/passkey MFA is code the team owns and must keep secure; a hosted identity provider would be less code but adds a FERPA subprocessor and recurring cost.
- A fixed worker pool with a manual scale control means deadline bursts rely on the deadline-window calendar and an operator, not an autoscaler.
- Single region and single Postgres instance (Multi-AZ) are the availability ceiling; the 99.5% target is met, 99.9% is not promised.
- Deferring COOP/COEP and WebGPU caps browser performance at single-threaded wasm and WebGL2; fine for S/M tiers, a rework if an L tier is ever needed in the browser.
- Diagnose, team projects, LTI/SAML and the second pack are all post-MVP; pilot institutions that require LTI grade passback on day one are not served by this MVP.

## Risks

| risk | mitigation |
|---|---|
| faer-sparse does not build or perform on wasm32, delaying the solver. | Week-1 spike with a hard decision date; fallback is an in-house CSparse-style simplicial LDLT with AMD (~2k lines) which is sufficient for S/M tiers; benchmark suite is written before the choice so either path is measured. |
| Cross-browser wasm numeric divergence (NaN canonicalization, SIMD lowering, future relaxed-SIMD) breaks the bit-identical promise between browser self-check and server grade. | No relaxed SIMD, no threads, libm for transcendental functions, golden hash equality across Chromium/Firefox/WebKit/Node in CI on every engine change; a mismatch is classified a platform fault (not a learner error), the server hash is authoritative and result_match records within_tolerance. |
| Only one or two engineers can write Rust, making the core a bottleneck. | Core scope is bounded and algorithmic (no UI); benchmarks and golden vectors come first so a second engineer can contribute against failing tests; the engine protocol is language-agnostic so a TypeScript Tier-S fallback implementation of the same interface remains possible. |
| Licensing blocks (AISC Shapes Database SaaS terms, ACI consent, ASCE hazard values) land late and force a pack redesign. | Steel-only MVP (R1) with the register gate from step 5; AISC license request in month 1 with the user-upload and computed-properties fallback behind a flag; ACI data isolated in its own bundle and feature-flagged off; named-site hazard set small, provenance-tagged and USGS-first. |
| LLM grades disagree with instructors in the first cohort or cost drifts upward. | 100% human review for summative grades (R11), golden-set gates before any grader promotion, agreement and override dashboards from the first submission, prompt caching with alerting on cache share, per-tenant budgets, batch mode for everything non-interactive, deterministic-only mode as the fallback. |
| Deadline burst overwhelms the fixed worker pool or the provider rate limit. | Deadline-window calendar triggers the scale-to-4 control and 24x7 coverage; deterministic results are released first; llm queue concurrency and jittered backoff never fail a job; the runbook was rehearsed with a synthetic 500-in-5-minutes load in staging. |
| Postgres becomes a single point of failure for both state and queue. | RDS Multi-AZ with automatic failover, PITR, rehearsed restore; the Jobs interface allows moving queues to Redis in v1.x; the workspace keeps working locally through API outages with queued segments. |
| Content effort (eight templates, 15-20 activities, golden submissions, SME verification) rivals engineering and slips the academic calendar. | Design-partner instructors author from month 1 on the JSON task format; the starter pack doubles as the regression suite so engineering consumes it continuously; Diagnose content is the designated first cut; plan backwards from term start with a 6-week content-ready buffer. |
| Scope creep from the 400 must-level requirements (plates, P-delta, team projects, LTI) starves the core loop. | ADR 0001 guardrails are the cut line; every v1.x feature has a named seam in this design (reserved schema fields, EngineRunner, Jobs interface, OpenTofu workspace, route groups) so saying 'later' is cheap and credible. |
| Operator console and impersonation become the highest-value attack surface. | platform_admin + MFA within 12 h, optional IP allowlist, reason-required writes, two-person rule on artifact promotion, consent-token impersonation with denylist and learner notification, console routes included in the authorization suite and the pentest. |
| Next.js upgrade churn (App Router, React 19, R3F v9/v10) destabilizes the workspace. | Pin versions per release, keep the workspace a feature module with the command bus as its only integration point, treat R3F v10 and WebGPU as watch items, cross-browser Playwright suite with pixel tolerance 0.5%. |
| Unit-cost math at pilot scale misses the $2.50 COGS per active learner-month target. | Fixed costs dominate at 200 learners (~$5); the target is met around 1,000 learners; track cost per analysis, per grade and per learner-month monthly and defer anything that adds fixed cost. |
