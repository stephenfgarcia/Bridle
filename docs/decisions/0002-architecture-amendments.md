# ADR 0002: Architecture amendments to ADR 0001

Status: adopted at the second plan approval (2026-11-03).
Date: 2026-11-03. Input: `docs/architecture/architecture.md` section 2 (amendments A1 to A4, proposed by the architecture), the adversarial polish pass of the assembled plan (A5 to A10), and the plan's section B9, which lists all ten.

Each row amends `docs/decisions/0001-mvp-scope-resolutions.md`: the new text replaces or extends the ADR 0001 row it names. Nothing else in ADR 0001 changes. Where a requirement document carried the superseded wording, the document now cites the amendment.

## Amendments (one row each; the new text is as the plan's B9 lists it)

| # | Amends in ADR 0001 | New text | Rationale |
|---|---|---|---|
| A1 | R14 (live latency contract) | The R14 live-latency contract attaches to the live band (predicted flops <= 2e8, DOF <= 6,000, cases <= 24, combinations <= 60, computed by the same symbolic analysis on both sides) and to two committed reference scenes (S-ref roof truss under snow and wind, about 150 members; M-ref 10-storey 6x6-bay 3D frame, 1,300 members, 20 combinations); Tier S and Tier M remain the size tiers, and Tier-M models above the band run in Run mode with progress. | The 300 ms figure cannot be met at 12k DOF; predicted work from the symbolic analysis is the FE domain's own routing basis and is computed identically in the browser and on the server (D04). |
| A2 | R1 (MVP resistance checks) | MVP resistance checks are AISC 360-22 LRFD W-shapes only at the B6 scope: D2, E3 for nonslender elements, F2 and F3, F6, G2, H1 with Mcy from F6, Table B4.1 classification per shape, Fy and use (the section allow-list is filtered from the shapes database at authoring time; refused shapes are listed to the author and reported as unsupported, never silently graded); HSS, pipe, E4, E7, F7 and ASD ship as pack minors after the pilot. | The first pack is the code, not data, and the starter course needs beams, trusses and W-section frames only (D18). F3 and F6 are one equation each; without them the standard teaching columns (W14x90, W14x99) would be refused and every 3D frame with weak-axis moment would be refused or graded unconservatively. |
| A3 | R1 and the content guardrail (MVP-01, CAT-03: Diagnose archetype) | The Diagnose archetype's error injector, grading path and content move to v1.1. Diagnose stays in the taxonomy and rubric schema, the seeded-error catalog and InjectedErrorSet schemas ship in the schema package, and the MVP course contains no Diagnose tasks (the Found errors panel ships behind a flag; "find the error" exercises are Check tasks and memo verification until v1.1). | Without the injector there is no per-seed InjectedErrorSet, no found/fixed scoring path and no calibration detectability test, so Diagnose tasks could be authored but not graded; the cut saves about 5 engineer-weeks. |
| A4 | None (adds a calendar decision ADR 0001 did not carry) | Formative-only friendly alpha in summer 2027 with one design-partner section and no credit-bearing grades; production-ready and content-ready 2027-12-01; first production pilot spring 2028; sized for four engineers plus a contracted Rust/FE engineer for months 1 to 6. | A fall-2027 production-ready date is unreachable at any credible estimate; the alpha validates the loop early and slips consume alpha scope before the pilot date (D20). |
| A5 | R4 (stability) | MVP stability is AISC 360-22 Chapter C with the Direct Analysis Method as default and the Effective Length Method opt-in per task (B6: DAM analyses strength combinations with 0.8EI and 0.8EA on every member, tau_b = 1.0 with the 0.001 alpha Yi notional load, Ni = 0.002 alpha Yi in every strength combination, B1 per member and B2 per storey from the reduced-stiffness analysis, K = 1.0, serviceability from a nominal-stiffness analysis; ELM with its B2 <= 1.5 and K = 1.0 at B2 <= 1.1 limits). B1 applies from T3 and B2 from T4; T5 adds the 12.8.7 theta check; CAT-04 loses its "T5+" restriction. Notional loads, mechanism detection and the slenderness advisories stay; iterative P-delta and eigenvalue buckling remain v1.x. | R4's "B1/B2 from first-order results with K = 1.0" is neither Chapter C method: it understates B2 and the column demand/capacity ratio, so the grader would pass unsafe frames, and Chapter C has no tier exemption. DAM is cheap to implement (a uniform stiffness factor on every member). |
| A6 | R1 (reinforced concrete at MVP) | RC appears in MVP only in Analyze tasks (reactions, member forces, deflections) with author-declared effective stiffness per ACI 318-19 6.6.3.1.1; no Check, Design or Optimize task may bind an RC member until the ACI pack ships, and the MVP course title drops Reinforced Concrete ("Structural Analysis and Design Fundamentals (Steel)"). Replaces R1's last sentence. | A Check task is graded against a hidden key from the checks library and no RC limit state exists in the catalog; "elastic section checks" for RC would fail correct designs (uncracked tension stress exceeds the modulus of rupture in every normally loaded beam) and teach that RC is proportioned by elastic stress. |
| A7 | R10 (auto-sized reference) | The auto-sized reference is iterated to a fixed point with re-analysis plus a bounded drift, B2 and theta loop: per member group the lightest catalog section passing all strength and member serviceability checks, re-analysed after each pass until stable, then a bounded system loop that upsizes the most drift-sensitive group until drift, B2 <= 1.5 and theta pass (at most 10 passes, within the D24 budgets), generated per seed at calibration time; a seed whose reference fails its final re-analysis is infeasible and the author reference is the benchmark. Replaces "greedy lightest passing catalog section per member group". | A single greedy pass is not a fixed point: changing sections changes self-weight, force distribution in indeterminate frames, B2 and storey drift, so the "passing" reference can fail its own re-analysis and economy would be scored against an infeasible benchmark. |
| A8 | LMS guardrail (gradebook) | "points-based gradebook with generic CSV export" becomes "points-based gradebook with generic plus Canvas- and Moodle-importable CSV export" (documented against each product's gradebook import format and covered by an import fixture test); weighted categories, drop-lowest and extra credit stay v1.x. | MVP-04's acceptance already requires the Canvas and Moodle import formats, LTI is v1.x so CSV is the only grade-of-record path for the pilot, and the layouts are a column header and one Points Possible row. |
| A9 | MVP guardrails and the must-requirements the cut list and the cards do not build (deferrals beyond ADR 0001) | Deferred beyond ADR 0001 by the cut list and the cards, listed so nothing drops silently: the similarity job and report (GAP5-FP-02/03; fingerprints stored from the first submission); the public self-serve sandbox (GTM-01, MVP-04(b), TOS-03; accounts by roster import, invite or join code); quiz types beyond the guardrail set; the docs site (HELP-08); DSR and impersonation UI (OPS-08/09; audited scripts instead); TL-01 linking; VP-01; VP-03; CA-02/03; LIB-02; CM-03 term rollover (needed before term 2, not term 1). | Each is a must-requirement that the architecture's cut list or the roadmap's cards do not build for the pilot; recording them here keeps the cut arithmetic honest and gives each a v1.1 home instead of a silent drop. |
| A10 | Content guardrail (eight starter templates; CAT-01 acceptance) and the architecture's cut list | The Q&A thread is removed from the cut list (built in P4-03 per the LMS guardrail "one Q&A thread per task"), and CAT-01's three-templates-per-tier acceptance is superseded by the eight-template guardrail (the eight starter templates named in the plan, all code-checked members W-shapes). | The cut list contradicted the binding guardrail; eight templates across T1 to T5 are what the content track can calibrate with 10 golden submissions each before the pilot. |
