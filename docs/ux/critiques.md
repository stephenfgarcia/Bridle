# Critiques of the surface designs

Two critic agents reviewed the five surface designs before synthesis; the synthesis resolved blockers and majors (see the change log at the end of ux-spec.md).

## Usability heuristics and accessibility critic: Nielsen's ten heuristics, WCAG 2.2 AA (including 2.1.4 character-key shortcuts, 2.1.2 no keyboard trap, 2.4.11 focus not obscured, 2.5.7 dragging alternatives, 2.5.8 target size, 2.2.1 timing, 4.1.3 status messages), the ADR R16 keyboard and screen-reader parity path for the 3D workspace (ACC-02, WS A11Y-01/02, LMS A11Y-02, NF-GAP3-08), cognitive load for first-year students (PRD-01, PER-12), error prevention in modeling (ERR-01..07, MOD-02/09, CAT-04) and consistency of patterns across the five surfaces.

The five designs are unusually strong on accessibility intent: the parity layout is a peer mode rather than a fallback, every canvas drawing has an HTML twin (legend, HUD, probe cards, evidence table, textual summary), colour is never the only channel (hatching above 1.00, dash-coded overlay severity, letter tags, icon-plus-word chips), live analysis state is always a word, scope and degraded conditions are shell-level banners, and the same EvidenceCard serves self-check, feedback and review. Error prevention in modeling is well covered where it matters most for first-years (snap tooltip with coordinates before the click, coincident-node merge with Undo, mechanism cause-first messages with one-click fixes and animation, locked elements impossible rather than flagged, cap meter disabling tools, unit-aware inputs with conversion-fingerprint hints, missing-combination Add actions). Three findings are blockers under the stated procurement obligations (ADA Title II / WCAG 2.1 AA, which 2.2 AA covers): (1) single-character shortcuts in the shell, workspace and review surfaces have no off switch and are not scoped to the focused component, failing WCAG 2.1.4 Level A under the MVP guardrail of fixed, non-remappable shortcuts; (2) a dozen workspace shortcuts collide with browser or OS bindings (Ctrl/Cmd+1-9, Alt+1-6, Alt+D, Ctrl+D, Ctrl+Shift+N, Ctrl+Shift+C, Ctrl+Shift+P, Ctrl+Shift+S, Ctrl+M, F6), violating EDIT-04 and the design system's own rule; (3) hard-required PNG snapshots cannot be produced in the Tables layout that is forced on no-WebGL lab machines, so Submit stays disabled on the very path R16 and ACC-02 exist for. Below the blockers, the biggest risk is divergence between the five designs on things the learner meets daily: four route schemes, two learner home pages, two task-page structures, five AI-provenance label sets versus PRD-02's fixed strings, three live-state and three severity vocabularies, two banner-stacking policies, three relative-date rules, and an unbudgeted stack of shell bar + workspace header + view bar + exam banner at 1280x720. First-year cognitive load needs trimming on the three screens they use most (task page, workspace status bar, submit dialog): tier codes, archetype nouns, pack versions, model tiers, outcome ids, SHA-256 hashes and pin sets are internal taxonomy that should sit behind a Details disclosure. Process note: the relayed user request about the Bridle Build Monitor (uncompressed layout, working versus idle agents, progress board, current-phase activity) is outside this card's product surface and was already implemented in commit fdb22a2 ("Monitor v3", tools/monitor/index.html, 405 insertions); nothing in PLAN-03 touches it and the orchestrator should confirm with the user that no further monitor changes are wanted rather than route that request into this card.

### Blocker (3)

- **Keyboard accessibility (WCAG 2.1.4 Character Key Shortcuts, Level A) · IA app shell keyboard_and_a11y (g h, g t, g c, g i, g r, g g chords; '[' toggle rail; '/' palette; '?' help); 3D workspace WS-01 and WS-12 (V, N, M, S, L, A, T, P tool keys; 1-7, 5, F, Home, +, -, Delete); instructor Review queue (j, k, a, x, r, /) and Review screen (E, R, 0-3 set a level); design-system accessibility sheet keyboard map**: Single-character shortcuts are active whenever focus is not in a text input or the canvas, and the MVP guardrail fixes shortcuts (no remapping). WCAG 2.1.4 requires that such shortcuts can be turned off, remapped, or be active only while the relevant component has focus. None of the five designs provides an off switch (the IA Settings > Accessibility section lists parity default, reduced motion and contrast only), and the review surfaces attach grade-affecting actions to single keys ('a' accepts an AI proposal, '0'-'3' set a judged level) with no confirmation or undo. Speech-input users (Dragon) and users with tremor will trigger tool changes, navigation and grade actions by accident. Fix: Scope every single-key shortcut to the focused composite widget so the 2.1.4 'active only on focus' exception applies: tool and camera keys only while the canvas container (role=application) has focus; j/k/a/x only while the queue grid has focus; 0-3 only as radio choices while the level group has focus; drop the global '[' and '/' keys (Ctrl/Cmd+K already opens the palette). Add Settings > Accessibility > 'Single-key shortcuts: on/off' (persisted, global) that keeps modifier shortcuts and the g-chords off by default for screen-reader users. Grade-affecting keys show an Undo toast. State the rule once in the design-system keyboard map and test it in the axe/manual pass.
- **Keyboard accessibility / browser-reserved shortcuts (WS EDIT-04 acceptance; design-system rule 'no conflicts with browser defaults') · WS-03 (Ctrl+Shift+N focuses the coordinate field; Ctrl+M move by vector); WS-05 (Ctrl+Shift+P cycles probes); WS-06 (Alt+D diagnostics dock); WS-07 (Ctrl+Shift+C run self-check); WS-01/WS-12 (Alt+1..6 rail tabs; Ctrl+1..9 switch load case; Ctrl+D duplicate); WS-13 (Ctrl+Shift+S capture); design-system Notifications (F6 cycles to the toast region)**: These combinations are browser or OS bindings that users rely on and that pages cannot always intercept: Ctrl/Cmd+1..9 switch tabs in Chrome, Edge and Firefox; Alt+1..8 switch tabs in Firefox on Windows/Linux; Alt+D focuses the address bar in Chrome, Edge and Firefox; Ctrl+D bookmarks the page; Ctrl+Shift+N opens an incognito/InPrivate window; Ctrl+Shift+P opens a Firefox private window; Ctrl+Shift+C enters DevTools inspect mode in Chrome/Edge; Ctrl+Shift+S is Firefox's screenshot tool; Ctrl+M mutes the tab in Firefox and Cmd+M minimizes the window on macOS; F6 cycles browser panes. A learner pressing Ctrl+2 to view combination C2 lands on another browser tab mid-exam. Fix: Create one shortcut registry (the workspace command registry already proposed in commands/commandBus.ts) that every surface reads from, with a per-OS/per-browser reserved-combination denylist and a CI test that fails on any collision or duplicate. Re-bind the listed commands to unreserved combinations or to leader chords inside the canvas (the shell already uses g-chords): load cases via the case switcher pill, the palette and a modifier-free chord when the canvas has focus; rail tabs, diagnostics, self-check, snapshot and move-by-vector via the palette plus registry-verified combinations. Publish the final map once in the shortcut sheet, Settings cheat sheet and help pages.
- **R16 parity path / keyboard-only submission (ACC-01, ACC-02, LMS A11Y-02, NF-GAP3-08, GAP3-DLV-14) · WS-13 Snapshot capture ('Capture for requirement' renders a PNG from the canvas); WS-08 Deliverables checklist (required snapshot is hard-required and blocks Submit); WS-11 Tables layout (forced on no-WebGL machines, no canvas); learner-journey Deliverables dock Snapshots tab; IA flow 'Institutional learner' failure path (lab machine without WebGL2 routed to the tabular editor)**: Required snapshots are PNG renders of the WebGL canvas. A learner on a lab PC without WebGL2 (the exact case ACC-02 and GAP4-HELP-03 route to the Tables layout) or a screen-reader user working in the parity layout has no canvas to capture, the checklist item stays 'not captured', and the Submit button stays disabled with '1 item missing'. The task is therefore not completable on the parity path, contradicting ACC-01 ('every learner flow including task submission completable keyboard-only'), R16 and NF-GAP3-08. The requirement itself is verified from the view-state sidecar (overlay, combination, preset), not from pixels, so the image is not needed for grading. Fix: In the Tables layout, 'Capture for requirement' builds the sidecar from the requirement (overlay, combination, view preset) and requests a deterministic server-side or offscreen render in the print canvas theme (the same renderer that already must produce deterministic screenshots per CAP-01); the checklist shows 'Generated from your view state' and the generated image gets alt text from the textual summary. If rendering is unavailable, the checklist marks the requirement satisfied by the sidecar with a note to the instructor. Add a required-snapshot task to the keyboard-only and no-WebGL e2e scripts for every archetype.

### Major (20)

- **Cross-surface consistency: routes and duplicate screens · IA sitemap (/o/:org/learn/courses/:offering/activities/:activity, /learn/grades, /learn/outcomes v1.x); learner journey (/home, /courses/:offeringId/tasks/:taskId, /progress, /courses/:offeringId/progress); 3D workspace (/offerings/:offeringId/tasks/:taskId/workspace, /sandbox/:modelId); instructor/author (/teach/offerings/:offeringId/review, /author/tasks/:taskId/edit); IA 'Learner home' vs learner-journey 'Learner home' (greeting-free h1 'Home' with unit switch, Open sandbox and Tutorial vs 'Good morning, Jordan' with Resume/Due/Grades/Outcomes); IA 'Task page' (tabs Brief | Given data | Deliverables | Submissions | Feedback | Q&A | Help) vs learner-journey 'Task page' (two-column scrolling page with Skip-to-rubric link)**: Four route schemes and two full designs each of the learner home and the task page. Deep links, breadcrumbs, the palette 'Navigate' group and the 403 reasons all derive from the route table, so the divergence is not cosmetic; learners would also meet two different task-page structures depending on which design is built first. Fix: Adopt the IA route table (routes.ts under /o/:org) as the single source and rewrite the other three designs' routes to it. Synthesize one home (IA frame and regions; learner-journey content for Resume, Due, Grades to read; no greeting; unit switch moved to Settings) and one task page (learner-journey's single scrolling page with the PRD-01 above-the-fold facts, keeping IA's Submissions, Feedback and Q&A as sub-routes rendered as navigation links, not tabs). Mark the superseded screens as such in the synthesis.
- **Consistency and PRD-02 conformance: AI provenance labels · IA ProvenanceLabel ('AI-provisional', 'Reviewed by <name>', 'Adjusted by <name>', 'Under appeal', 'Under re-verification', 'AI feedback pending', 'Assisted by operator'); WS-09 provenance strip ('AI-generated feedback - not professional engineering advice · Reviewed by Dr. Lee, Nov 2' / 'AI-provisional - not yet reviewed by an instructor'); learner-journey feedback header ('[AI-generated, confirmed by instructor]' + 'Reviewed and released by Dr. Alvarez'); instructor ProvenanceLabel ('AI proposed', 'AI-provisional', 'Confirmed by <name>', 'Adjusted by <name>', 'Regraded under <grader version>'); design-system ProvenanceLabel ('Deterministic check', 'AI proposed', 'AI-generated, pending instructor review', 'AI-generated, confirmed by <name> on <date>', 'Overridden by <name>', 'Carried from version n', 'Manual grade')**: Five enumerations with different wording for the same states, while PRD-02's acceptance fixes the exact learner-facing strings 'AI-generated, pending instructor review' and 'AI-generated, confirmed by instructor', GRD-03 requires naming the reviewing instructor, and every design claims to use 'one vocabulary'. Learners would see 'Reviewed by', 'confirmed by', 'Adjusted by' and 'Overridden by' for overlapping meanings across home, gradebook, feedback and receipt. Fix: Define ProvenanceLabel once in the design system with the PRD-02 strings as the primary text and one secondary line per state: 'Reviewed by <name>, <date>', 'Adjusted by <name> (reason)', 'AI feedback pending', 'Under appeal', 'Under re-verification', 'Instructor graded (no AI)', 'Auto-submitted at close'. Every other design references the component; a snapshot test guards the strings; 'Overridden' is staff-only vocabulary (audit log), never shown to learners.
- **Consistency: status, severity and live-state vocabularies · WS-06 diagnostics (Error / Warning / Notice); WS-09 overlay (Fail / Warning / Note); WS-07 and design-system evidence severity (Critical / Major / Minor / Advisory); design-system StatusChip (Pass / Warn / Fail / Not checked / Error / Pending review); learner journey (Pass / Warn / Fail; pipeline 'Received, Re-analyzed, Checks done'); design-system GradingStatusTimeline ('submitted, analyzed, checked'); WS live-state (Fresh / Running / Stale / Paused / Failed / Validity only) vs design-system LiveStatePill (Live / Solving… / Stale / Live paused / Unstable / Offline); IA StatusChip (adds 'overdue', lacks 'Held') vs learner-journey TaskStatusChip (adds 'Held', 'Exam')**: A first-year meets 'Warning', 'Warn', 'Note', 'Notice', 'Advisory' and 'Minor' for overlapping ideas on adjacent panels, and 'Running' versus 'Solving…' for the same analysis state. The workspace design itself says 'never mix the sets on one surface' but the self-check panel shows Fail/Warn/Pass rows next to 'advisory' items and 'Error' states. Recognition over recall fails when the same concept has three names. Fix: Freeze in the design-system copy sheet: model diagnostics = Error / Warning / Notice; check and evidence status = Pass / Warn / Fail / Not checked / Pending; severity (Critical / Major / Minor / Advisory) only as a secondary staff-facing label and in gate copy; one live-state set (Fresh, Solving, Stale, Paused, Unstable, Offline) used by the pill, the legend badge and the live region; one pipeline stage list (Received, Analyzed, Checked, AI feedback, Instructor review, Released) shared by receipt and timeline; one task-state list including Held and Overdue.
- **Layout budget at the minimum viewport (NFR-3D-07, INP-02) and header ownership · IA app shell ('the full-screen workspace route keeps only a slim top bar' with Back, task title, autosave, help, bell); WS-01 header task strip (44 px: back, title, archetype/tier chip, ownership, policy chips, profile chip, Submit, ?); WS-01 canvas view bar (presets, projection, style, labels, color-by, fit) above the canvas; design-system 'Workspace vertical budget at 720 px: exam banner 40 + toolbar 44 + status 28'; WS-01 bottom dock 220 px when open**: The designs stack a shell slim bar, a workspace task header, a view bar, an exam banner and an open dock, but the design-system budget counts only three bars. At 1280x720 with the dock open the canvas falls to roughly 300 px high, and it is unclear whether the shell bar and the workspace header coexist. The 60% canvas width promise is also only stated with one rail open and never checked against the 240 px shell rail. Fix: One header: the workspace header replaces the shell top bar on the workspace route (merge IA's slim-bar items into WS-01's 44 px strip; the bell is hidden in exam mode anyway). The view bar becomes a HUD overlay inside the canvas as the design system already proposes. Restate the vertical budget with the dock collapsed by default and the banner slot, and add a layout test at 1280x720 and 1366x768 that asserts canvas width >= 60% and height >= 500 px with one rail open.
- **ARIA pattern misuse on route-changing navigation (WCAG 1.3.1, 4.1.2; Nielsen consistency and standards) · IA Course page ('Tabs follow the WAI-ARIA tabs pattern with arrow-key movement'), IA Task page tabs, IA context-header entity tabs (Outline | Tasks | Grades | Discussions | Announcements; Overview | Review | Gradebook ...), IA Settings section tabs ('vertical tablist')**: These tabs change the route, and the shell moves focus to the page h1 on every route change. With the ARIA tabs pattern, arrow keys would switch sub-routes and yank focus away from the tablist on each press; screen readers announce 'tab 2 of 5' for what is a page change. Automatic activation plus h1 focus is a focus trap in reverse. Fix: Render route-changing tabs as a navigation landmark of links styled as tabs with aria-current='page' (tab-styled nav). Keep role=tablist only for in-page panels that do not change the URL (results dock tabs, feedback Criteria/Narrative/Memo claims, builder section rail if it is in-page).
- **ARIA tree with interactive children (WCAG 4.1.2; screen-reader operability of the learner hub) · IA Course page outline ('Outline is a tree (role=tree) with modules as expandable nodes' containing Resume, Start, Why? buttons per activity row)**: Treeitems cannot contain focusable controls in the tree pattern; screen-reader users in browse mode cannot reliably reach the per-row actions, and arrow-key navigation competes with the buttons' Tab stops. This is the learner's main hub between home and the task page. Fix: Use nested lists: each module is a disclosure button (aria-expanded) over a list; each activity is a list item with a link (type, title, status, due in the accessible name) and its single action button. Keep type-ahead as a visible filter input instead of tree type-ahead.
- **Keyboard trap and inconsistent grid keys (WCAG 2.1.2) · WS-11 Tables layout interactions ('Arrow keys move between cells; Enter edits; Esc cancels; Tab next cell'); WS-08 findings grid ('Tab order follows the row layout; Enter adds a row (Ctrl+Enter in grids)'); design-system keyboard map ('tables: arrows, Enter fly-to, Space pick')**: Tab moving to the next cell turns a 2,000-row members table into a keyboard trap (Tab never leaves the table) and contradicts the design-system map where arrows move and Tab leaves. Enter means 'edit' in one table and 'add a row' or 'fly to' in others. Fix: One grid contract: arrows move cells, Tab and Shift+Tab leave the composite, Enter or F2 edits, Esc cancels, Ctrl+Enter adds a row, Space selects, Delete removes with confirmation; fly-to is a row action button or Ctrl+Enter in result tables. Document in the keyboard map and reuse the same DataTable component.
- **Error prevention in modeling: accidental node move versus orbit · WS-01 interactions ('LMB-drag on empty space orbits (window-select in Select with Ctrl/Cmd)'); WS-03 ('Drag over an existing node: target highlighted; on drop a small chooser Merge into N4 / Cancel'); EDIT-01 gizmo rules**: In Select mode a plain drag that starts on a node moves geometry while a drag that starts one pixel away orbits the camera. First-years trying to orbit will drag nodes (and hit the merge chooser), and unlike merges there is no Undo toast for moves. On a 1366x768 trackpad this is the most frequent accidental edit in CAD-style tools. Fix: In Select mode a drag on an entity never moves it (orbit on empty space, marquee with the modifier); moving requires the gizmo handles or the Transform tool (T), and the first move in a session shows 'Moved N7 by 0.500 m [Undo]' exactly like the merge toast. Locked geometry already blocks moves; make the rule explicit in the pointer-mapping table and the help page.
- **Cognitive load for first-year learners (Nielsen: aesthetic and minimalist design; match with the real world) · IA content_and_copy ('tasks carry tier (T1-T6) and archetype (Analyze, Check, Design, Optimize, Diagnose)'); IA Task page fact line ('T4 Design Summative Individual 100 pts', 'Grading target: best', 'Randomized: your variant', 'US pack v1.2 (ASCE 7-22, AISC 360-22)'); IA course header ('US pack v1.2 US units'); WS-01 header chips ('Personal', 'Individual · AI: disclose', '● Coach'); WS-01 status bar ('● Fresh 38 ms · Tier S'); IA home and learner-journey outcome bars ('L1', 'L2', 'L1.3')**: Internal taxonomy codes (task tier, archetype noun, pack version, model tier, outcome ids, assistance preset names, cryptic chips such as 'AI: disclose') appear on the three screens a first-year uses most. A week-one student does not know what 'T4', 'Design task', 'US pack v1.2', 'Tier S' or 'Coach' means, and the task page already carries 14 facts above the fold. Fix: Learner copy uses plain phrases: 'Design task', 'Individual work', 'AI tools allowed with disclosure', 'Help available: coach mode (unlimited self-checks)'; hide T-tier and model-tier codes from learner views; show code names ('ASCE 7-22, AISC 360-22') with the pack version only inside a Details disclosure; outcome names without L-codes; give every remaining term a glossary tooltip bound to a help id. Keep the facts line to due, attempts, late policy and units.
- **Cognitive load at the moment of highest anxiety (submit) · Learner-journey Submit dialog (SHA-256 per deliverable, resultHash, pin set 'task v3 . rubric v3 . engine 2.3.1 . checks 1.4 . clause lib 1.2 . scenario seed 8f21', Copy all hashes); WS-08 submit dialog ('Model a81f…c2 (analysis fresh)')**: The dialog shows about nine technical identifiers before the pledge checkbox. The decision-relevant content (what is in the bundle, on-time or late with the penalty, policy disclosures, pledge) is diluted, and the design's own risk list admits hashes intimidate learners. Fix: Keep 'What will be submitted' as plain counts and names, the timing line, the policy and pledge; move hashes, pins and seed into a collapsed 'Technical details (for your receipt)' disclosure with Copy all hashes inside it. The receipt page keeps the full detail by default.
- **Honesty of grade provenance and error prevention in grading (PRD-02, PRD-03, R11) · Instructor Review queue bulk bar ('select all unflagged (9)', 'Accept AI proposal (9)') and Review screen ('Accept all AI proposals', 'a accepts the AI proposal for an unflagged row', '0-3 set the level on a judged card'); learner label after release 'AI-generated, confirmed by instructor'**: A grade bulk-accepted without anyone opening the submission is shown to the learner as 'confirmed by instructor', which misstates what happened; single-key accept and single-digit level changes have no confirmation or undo, so a stray key press changes a grade (the reason field only guards adjustments, not accepts). Fix: Record action=bulk_accept in the audit and render learner provenance as 'Reviewed by <name> (accepted without changes)' for bulk-accepted grades; enable bulk accept only after the deterministic summary of the selection has been expanded or at least one submission of the task opened; level keys act only as radio choices when the level group has focus; accept actions show an Undo toast and are reversible until release.
- **Parity path: analysis state announcements (WCAG 4.1.3 status messages; ACC-02) · WS-11 Tables layout ('SUMMARY (text; updates after each analysis)'); WS-01 keyboard_and_a11y ('Live-region narration of canvas changes is v1.x; at MVP selection and analysis results are readable through the Props panel, the status bar and the textual summary'); design-system LiveStatePill ('announces changes through a polite live region')**: R16 defers per-change narration, but without a single status announcement a screen-reader user editing a table cell cannot know when the solve finished, failed or was blocked by errors, so they do not know whether the result tables and summary they are about to read are current. The design system specifies the live region; the workspace design does not commit to it at MVP. Fix: Make one polite status live region an MVP requirement for analysis-state transitions only ('Results updated', 'Results stale, solving', 'Analysis blocked: 2 errors', 'Live paused'), plus the self-check and submit completions already specified; the textual summary's first line carries the state and timestamp. Keep per-change narration v1.x.
- **Visibility of system status at the minimum width (status bar) · WS-01 status bar (working plane, snap, units, selection summary, cap meter, analysis chip, Live menu, autosave, 'ⓘ records', disclaimer badge in 28 px); WS risks ('status-bar chips truncating to icons with tooltips at narrow widths')**: Ten controls in a 28 px bar at 1280 px leave about 120 px each, so the chips collapse to icons at the MVP minimum, hiding the two things the design calls 'always honest' (analysis state words and cap meter) and leaving icon-only buttons that need accessible names, tooltips and 24 px targets. 11-12 px chip text would also breach the design system's 13 px minimum for data rows. Fix: Define a retention order (analysis state, cap meter, autosave, selection) that keeps text at 1280 px and collapses plane, snap, units, records and disclaimer into an overflow menu; the analysis state is never icon-only; every chip is a button with an accessible name and a tooltip; minimum chip text 13 px.
- **Memo authoring usability · WS-08 Memo tab inside the 320 px right rail (8 section cards, toolbar B/I/list/math/table/fig, 400-1,200 words); learner-journey open question ('the memo editor needs at least 360 px'); design-system panel width 280-480 px**: Writing an eight-section engineering memo with LaTeX and figures in a 320 px column beside a 3D canvas is cramped, error-prone and discourages revision; the two designs disagree on the minimum width and neither defines where a learner writes the long form. Fix: Make the task-page mirror (full width) the default place to write the memo, with the dock showing per-section counts and an 'Open memo editor' action; alternatively allow the rail to expand to 480 px or detach as a second column at 1440 px and up. The plain-text mode stays available in both.
- **User control and freedom (guided lessons) · WS-02 states ('optional auto-advance after 1.5 s'); learner-journey Guided lesson states ('Met: green check, Next enabled; optional auto-advance after 1.5 s (off under reduced motion)')**: Advancing the instruction and highlight target without a user action is disorienting for screen-reader users and for first-years still reading the step; it also moves content while the learner's hands are on the model. Fix: Remove auto-advance; announce 'Checkpoint met' politely, enable Next, and let the learner advance (Enter on Next). Keep the dots and progress as feedback.
- **Error prevention: support preset semantics for intro tasks · WS-02 Properties ('Support: [none] [pin] [roller-X] [roller-Z] [fixed] Tx □ Tz □ Ry □'); WS flow 'First analysis on a 2D intro task' failure path ('Roller orientation leaves a mechanism (roller-Z instead of roller-X)')**: 'roller-X' does not say whether X is the free or the restrained direction; the design's own failure path shows the mechanism that results from picking the wrong one. The DOF checkboxes are the only disambiguation and they use restraint semantics ('Tz restrained') while the preset name uses the free direction. Fix: Name presets by behaviour and show the glyph with its arrow: 'Roller, free in X (restrains Z)', 'Roller, free in Z (restrains X)', 'Pin (restrains X and Z)', 'Fixed'; the preset's accessible name lists the restrained DOFs; in T1 tasks show a one-line 'What this support does' under the preset.
- **Consistency: exam-mode signalling and announcements (GAP5-EXAM-03) · IA app shell ('exam countdown announcements at 30, 10, 5 and 1 minutes which are assertive'); WS-10 ('aria-live announcements at 30, 10, 5 and 1 minutes; banner color unchanged (no alarm color shifts), text Less than 5 minutes left added'); learner-journey ExamStrip ('strip turns to the warning accent at 5 minutes'); design-system ('polite; assertive at 1 minute')**: Three different politeness rules and two different colour behaviours for the same countdown; assertive announcements every time interrupt a screen-reader user mid-edit, and a colour shift at five minutes contradicts the 'no alarm colour shifts' rule. Fix: One rule in the design system, referenced by the others: polite at 30, 10 and 5 minutes, assertive at 1 minute; banner colour unchanged with the text 'Less than 5 minutes left' added; the visible number never animates.
- **Consistency: banner stacking policy · IA banner slot ('stacked, max 2 visible, rest in a +1 more disclosure'); design-system ModeBanner ('one at a time by priority exam > impersonation > view-as > offline > degraded > preview > live view; others queue into the status bar as chips')**: Contradictory rules change the vertical budget (40 px vs 80 px plus a disclosure), the live-region behaviour and what the learner sees during deadline weeks when incident, degraded and freeze banners coincide. Fix: Adopt the design-system one-at-a-time rule with the IA's full priority list (exam > impersonation > view-as > offline > degraded grading > preview > read-only tenant > incident > change freeze) and show the queued banners as status-bar chips with a disclosure; update the IA shell wireframe.
- **Settings completeness for accessibility and appearance · IA Settings screen (Profile, Display and units, Accessibility: parity default, reduce motion, high-contrast element colors, keyboard cheat sheet); design-system flows ('Settings > Appearance offers Theme, Density, Canvas background'; 'users can disable the deformed animation and the stale pulse independently of the OS setting in Appearance settings'); design-system Encodings ('pattern-only mode is reachable from the legend menu ... the choice persists per user')**: The settings screen that is designed lacks the theme, density, canvas-theme, animation and pattern-only controls that the design system assumes exist, and no screen offers the single-key shortcut switch required by the 2.1.4 finding. Fix: Add an Appearance section (theme System/Light/Dark, density Auto/Compact/Default/Comfortable, canvas background Auto/Light/Dark/Print preview) and extend Accessibility with: open tasks in the tabular layout by default, reduce motion, high-contrast element colours, pattern-only results mode, deformed-shape animation on/off, stale pulse on/off, single-key shortcuts on/off, keyboard cheat sheet.
- **Design-system self-contradiction: colour jobs · Design-system tokens (--viz-diag-N:#5B66E6 equals --accent-500; --viz-diag-V2/V3/M2/M3/T reuse the Okabe-Ito load-case hues and the axis colours; --mode-impersonate-bg uses red-600)**: The first principle says accent is never a data colour and red appears only for Fail, over-utilization and destructive actions, yet the axial-force ribbon is the selection indigo (a selected member and its N diagram are indistinguishable by hue) and the impersonation banner is red. Hue reuse between diagram components, load cases and axis handles is acknowledged but the accent collision is not. Fix: Give N a hue outside both the accent and the categorical set (for example a teal) or draw diagram ribbons from a dedicated six-hue palette validated under CVD; render selection with the double outline plus halo so hue is never the only selection cue; move the impersonation banner to a plum or amber variant with the countdown, or document red as an explicit exception.

### Minor (8)

- **Design-system factual claim about colormap bands · Design-system Encodings states ('every band separated by at least a 3:1 luminance step from its neighbours extremes')**: Ten sequential cividis bands cannot each differ from their neighbours by 3:1 (bands 01 #00204D and 02 #00336F differ by roughly 1.2:1); the claim will fail its own CI test. The real guarantee is numeric labels, hatching at and above 1.00 and the pattern/isoline mode. Fix: Restate the acceptance: legend swatches at least 3:1 against the legend background with a 1 px border, monotonic lightness under deuteranopia/protanopia/tritanopia simulation, and the pattern mode as the non-colour channel; keep the hatch and outline rules for 1.00-1.02 and above 1.02.
