# P0-02.2 Docker compose stack and pnpm dev smoke

## Spec

What: the local stateful services as docker compose, and a `pnpm dev` that brings them up and proves them.
Acceptance criteria:
1. `docker-compose.yml` (or `compose.yaml`) defines `postgres` (PostgreSQL 16, named volume, healthcheck via pg_isready, port 5432), `minio` (S3-compatible, console port, healthcheck, a bootstrap that creates the `bridle-dev` bucket), `mailpit` (SMTP 1025, UI 8025); all images pinned by tag; credentials are dev-only defaults from `.env.example` (committed) and never from `.env.local`.
2. `pnpm dev` (or `pnpm dev:services`) runs `docker compose up -d --wait`, then verifies: a `SELECT 1` against Postgres, the MinIO health endpoint and bucket existence, the mailpit API; prints one line per service and exits 0; `pnpm dev:down` stops them; a second `pnpm dev` is idempotent.
3. `docs/ops/local-dev.md` documents the services, ports, credentials file, and how to reset volumes.
4. A test `tools/test/compose.test.sh` asserts the compose file parses (`docker compose config`), the three services are healthy after `pnpm dev`, and the bucket exists.
Out of scope: application containers (P0-02.4), migrations.
Files: compose.yaml, .env.example, docs/ops/local-dev.md, tools/dev.sh or package.json scripts, tools/test/compose.test.sh.
