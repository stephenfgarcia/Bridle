# P0-02.3 Actions PR workflow proven on a pushed branch

## Spec

What: the pull-request workflow on GitHub Actions that runs `pnpm check`, proven on a pushed branch, and the required-status-check wiring.
Acceptance criteria:
1. `.github/workflows/check.yml` runs on pull_request and on push to main; path filters skip pure-docs changes (docs/**, factory/**, *.md) for the heavy jobs; jobs: `check` (ubuntu-latest, node 22 from .node-version via setup-node with pnpm cache, Rust from rust-toolchain.toml via dtolnay/rust-toolchain, sccache via mozilla-actions/sccache-action, `pnpm install --frozen-lockfile`, `pnpm check`, `bash tools/doctor.sh --ci` or an equivalent CI subset) and a lightweight `docs` job for filtered paths that always reports the `check` status green so the required check never blocks docs-only PRs.
2. Proven on a real branch: the builder pushes `lane/p0-02-3-ci` (or `ci/p0-02-3`), opens a PR with `gh pr create`, the `check` job passes, the PR is merged with `gh pr merge --squash` (or the foreman merges at ship), and the run URL is recorded in `## Build`.
3. Branch protection on main gains `check` as a required status check (`gh api -X PATCH .../protection/required_status_checks` by the foreman at ship), and card P0-06.3's two manual gates are ticked (`[x]`) in its frontmatter by the foreman with the proof commands from docs/ops/github.md.
4. `docs/ops/github.md` item (c)/(e) updated: the workflow name, the required check, and the lane-branch flow.
Out of scope: wasm host matrix (P0-09), deploy workflows.
Files: .github/workflows/check.yml, docs/ops/github.md, factory/cards/P0-06.3-*.md (gates), tools/doctor.sh only if a --ci flag is needed.
