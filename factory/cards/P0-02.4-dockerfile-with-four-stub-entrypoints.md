# P0-02.4 Dockerfile with four stub entrypoints

## Spec

What: one container image with four stub entrypoints, as the architecture's deployment unit.
Acceptance criteria:
1. `Dockerfile` (multi-stage: pnpm install with the lockfile, build, runtime on a pinned node:22 slim image, non-root user) builds the workspace and exposes an entrypoint script `tools/entrypoint.sh` that dispatches on its first argument: `web`, `worker`, `judge`, `system` (each a stub that prints its name, the git sha, and exits 0 or stays alive on a `--serve` flag with a health endpoint for web).
2. `docker build -t bridle:dev .` succeeds on this machine (OrbStack); `docker run --rm bridle:dev web` prints `web <sha>`; an unknown entrypoint exits 2 with usage.
3. `.dockerignore` keeps node_modules, target, .bridle, .git, docs out of the context; image size is recorded in `## Build`.
4. A test `tools/test/image.test.sh` builds the image (reusing cache) and asserts the four entrypoints and the unknown-entrypoint behaviour.
Out of scope: pushing the image anywhere, Rust compilation in the image (the wasm artifacts arrive later), compose integration.
Files: Dockerfile, .dockerignore, tools/entrypoint.sh, tools/test/image.test.sh, docs/ops/local-dev.md (one section).
