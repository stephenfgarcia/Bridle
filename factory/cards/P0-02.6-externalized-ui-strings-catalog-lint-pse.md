## Spec

What: externalized UI strings from day one (I18N-01): an ICU MessageFormat catalog, a lint that fails on hard-coded user-facing strings in apps/web, and a pseudo-locale build.

Decisions (each with its reason):
- Lint form: a Node script, `packages/i18n/lint/lint-strings.mjs`, run by `pnpm lint` after Biome (`"lint": "biome ci . && node packages/i18n/lint/lint-strings.mjs"`), so it is step 1 of `pnpm check` and runs in Actions. Not a Biome plugin: the rule needs an allowlist file, stale-entry detection and same-file constant resolution, which a script over the TypeScript syntax tree does in one place and a fixture test can drive by exit code. It lives in the package, not in `tools/` (the Spec's "or tools/lint-strings.*"), because its unit test then runs under the package's vitest in `pnpm check` step 3 with turbo hashing the right inputs, and because it needs the classic TypeScript compiler API: typescript 7.0.2 ships none (`packages/units/node_modules/typescript/lib` has no `typescript.js`), 6.0.3 does.
- User-facing positions (scanned: `*.ts` and `*.tsx` under `apps/web/src`, not `*.d.ts`, not `*.test.*`); a string "has a letter" when it matches `\p{L}`, "is prose" when it matches `\p{L}{2,}\s+\p{L}{2,}`:
  | Rule id | Flags |
  |---|---|
  | `jsx-text` | JSX text with a letter |
  | `jsx-expression` | a string or template literal with a letter in a JSX child expression (through `?:`, `&&`, `\|\|`, parentheses) |
  | `jsx-constant` | an identifier in a JSX child or in a user-facing attribute that the same file binds to a string literal with a letter (reported at the declaration) |
  | `jsx-attribute` | a string with a letter in `alt`, `title`, `placeholder`, `label`, `aria-label`, `aria-description`, `aria-placeholder`, `aria-roledescription`, `aria-valuetext` |
  | `property` | a string with a letter as the value of an object property named `title`, `description`, `label`, `message`, `error`, `detail`, `summary`, `heading`, `placeholder`, `alt` (Next `metadata`, JSON bodies of route handlers) |
  | `prose` | any other string or template literal that is prose |
  Never flagged: the first argument of a call to `t(...)` or `x.t(...)` (the catalog lookup); import and export specifiers; directives (`"use client"`); type positions; operands of `===`, `!==`, `==`, `!=` and `case` labels; arguments of `console.*(...)` and of `new <Name>Error(...)` (for developers); every other JSX attribute (`className`, `data-*`, `lang`, `href`, ...), except inside a function written in it.
- Allowlist: `apps/web/i18n-allowlist.json`, `{ "allow": [ { "file": "<path relative to this file's directory>", "text": "<the reported text>", "reason": "<why>" } ] }`; it ships as `{ "allow": [] }`. A finding whose file and text match an entry is not reported. An entry that matches nothing is "stale" and fails the lint (exit 1); an entry without `file`, `text` or a non-empty `reason`, or an unreadable file, is exit 2. Flags: `--src <dir>` (default `apps/web/src`) and `--allow <file>` (default the file above), both resolved from the repository root found from the script's own path.
- Output: one line per finding on stderr, `<path>:<line>:<column> <rule id> "<text, whitespace collapsed>"`, in file then position order, then `lint-strings: FAILED: <n> hard-coded user-facing string(s), <m> stale allowlist entr(ies); <k> files checked`, exit 1; else stdout `lint-strings: ok, <k> files checked, <a> allowlisted`, exit 0.
- Fixtures of the lint live in `packages/i18n/lint/fixtures/`. The repository's own lint does not trip on the failing one because the script scans only `--src` (default `apps/web/src`), Biome has no rule about literals (both fixtures are Biome-clean as written below), and the package's `tsconfig.json` includes `src` only.
- Compile-time ids: `packages/i18n/src/index.ts` imports `../messages/en.json` (`resolveJsonModule`) and exports `type MessageId = keyof typeof en`; the catalog is flat, ids are dotted keys. `t("no.such.id")` is a type error in the package and in `apps/web`. Values are `Record<string, string | number | boolean | Date | null | undefined>`: JSON gives no literal types for the message text, so a missing value is a run-time error of the formatter, not a compile error.
- ICU MessageFormat: a dependency, not a formatter of our own (plural rules, select, number and date skeletons and apostrophe escaping are the standard's, and I18N-01 names the standard). `intl-messageformat` **12.1.5** (BSD-3-Clause; `pnpm view`, published 2026-11-08) as a dependency of `@bridle/i18n`; `@formatjs/icu-messageformat-parser` **3.5.23** (MIT; the version 12.1.5 depends on) as a devDependency, for the pseudo generator. Transitive: `@formatjs/fast-memoize` 3.1.7 and `@formatjs/icu-skeleton-parser` 2.1.13 (both MIT). Exact pins; if a number has moved, the newest 12.x and the parser version it names, with the lookup in `## Build`.
- Locale: build time, `NEXT_PUBLIC_LOCALE` (`en` when unset or empty; any other value than `en` or `en-XA` throws, so a typo fails the build: proven with `fr`). Next inlines it, so one build is one locale; the API (`createTranslator(locale)`) leaves room for the per-user locale of I18N-01, which needs users and is a later row. The smoke runs once against the pseudo-locale as `NEXT_PUBLIC_LOCALE=en-XA pnpm e2e:smoke`: Playwright's `webServer` inherits the variable, and the spec reads the same variable to pick the catalog it expects.
- `messages/en-XA.json` is committed (the typed import, the Docker build and the smoke read it; nothing generates at build time). Drift guard: a vitest test asserts it deep-equals `pseudoCatalog(en)`, in `pnpm check` step 3; `pnpm i18n:pseudo` rewrites it byte-identically when nothing changed.

Environment (builder, tester): prefix `. "$HOME/.cargo/env"; . "$HOME/.nvm/nvm.sh"; nvm use 22 >/dev/null; export PATH="$HOME/.orbstack/bin:/usr/local/bin:$PATH";`. Stage nothing, commit nothing. Re-read a file before editing it. Stop any `next dev` of `apps/web` before a build.
