# P0-02.6 Externalized UI strings: catalog, lint, pseudo-locale

## Spec

What: externalized UI strings from day one (I18N-01): an ICU MessageFormat catalog, a lint that fails on hard-coded user-facing strings in apps/web, and a pseudo-locale build.
Acceptance criteria:
1. `packages/i18n`: message catalog `messages/en.json` (ICU MessageFormat), a typed `t(id, values)` helper with compile-time ids, and a pseudo-locale generator (`pnpm i18n:pseudo` writes `messages/en-XA.json` with accented, lengthened strings).
2. apps/web's page and health route use the catalog; a lint rule (eslint custom rule or a script in `pnpm lint`) fails on JSX text and string literals in user-facing positions that are not catalog lookups, with an allowlist file for exceptions; the rule has a unit test with one failing and one passing fixture.
3. `NEXT_PUBLIC_LOCALE=en-XA pnpm --filter web build` (or a runtime switch) renders the pseudo-locale, proven by the smoke test running once against it.
4. `docs/ux/ux-spec.md` is not changed; `docs/ops/i18n.md` explains the rule and the allowlist.
Files: packages/i18n/*, apps/web (catalog use), eslint rule or tools/lint-strings.*, docs/ops/i18n.md.
