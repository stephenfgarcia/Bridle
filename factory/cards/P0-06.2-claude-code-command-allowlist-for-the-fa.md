# P0-06.2 Claude Code command allowlist for the factory

## Spec

What: add the factory's permission allowlist to `.claude/settings.json`. The file already exists (committed by the monitor v4 card P0-10, commit 126d1f8) and carries three hooks (PostToolUse, PostToolUseFailure, SubagentStop) that must stay exactly as they are; this card merges a `permissions` object into it, nothing else.
Acceptance criteria:
1. `.claude/settings.json` is valid JSON with `permissions.allow` entries for: `Bash(cargo *)`, `Bash(rustup *)`, `Bash(pnpm *)`, `Bash(corepack *)`, `Bash(node *)`, `Bash(npx playwright *)`, `Bash(docker *)`, `Bash(docker compose *)`, `Bash(git add *)`, `Bash(git commit *)`, `Bash(git push *)`, `Bash(git rebase *)`, `Bash(git worktree *)`, `Bash(git switch *)`, `Bash(gh pr *)`, `Bash(tofu fmt *)`, `Bash(tofu validate *)`, `Bash(tofu plan *)`, `Bash(tools/monitor/*)`, `Bash(python3 tools/monitor/*)`, `Bash(bash tools/doctor.sh)`; and `permissions.deny` for `Bash(tofu apply *)`, `Bash(tofu destroy *)`, `Bash(aws *)` (no carve-out: deny always wins in Claude Code, so credential checks run inside scripts such as tools/doctor.sh or by the user), `Bash(git push --force*)`, `Bash(git push -f *)`, `Bash(git push * --force*)`, `Bash(git push * -f*)`, `Read(.env.local)`, `Read(.env.*.local)`. Spec amended at the plan station (foreman decision, 2026-11-03): the `aws sts get-caller-identity` allow is dropped as inert; the three extra force-push patterns are added.
2. `docs/ops/permissions.md` explains each allow and deny in one line and the rule that production credentials never reach station agents (docs/ops/secrets.md).
3. A test (`python3 tools/test/settings.test.py`) validates the JSON, asserts the three hooks are intact, asserts every allow entry and every deny entry above is present (seven destructive deny patterns plus the two Read denies), and that no allow entry duplicates a deny entry.
Out of scope: changing the user's global ~/.claude settings; touching the hooks block; any other file under tools/monitor.
Files: .claude/settings.json, docs/ops/permissions.md.


## Plan

Syntax verified 2026-11-03 against code.claude.com/docs/en/permissions and /settings: a rule is `Tool(specifier)`; in a Bash rule `*` matches any text, and the space-separated trailing form (`Bash(cargo *)`, which also matches a bare `cargo`) is the documented one (`:*` is an equivalent suffix); `Bash(git push --force*)` has no space, so it also matches `--force-with-lease`. "Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, and rule specificity doesn't change the order. A broad deny rule like `Bash(aws *)` blocks every matching call, including calls that also match a narrower allow rule". A bare `Read(.env.local)` is relative to the session's working directory and, as a deny, matches at any depth (gitignore semantics), including `cat`/`head`/`sed` and redirections in Bash. `permissions.allow` lists merge across the user, project and local files; a deny in any file wins; project allow rules apply only in a trusted workspace; Claude Code reloads the file on save.

Steps (builder: 1 to 3; nothing under `tools/monitor/` and no hook entry is edited):
1. `.claude/settings.json` (change): run a throwaway standard-library program from the repository root (`python3 - <<'PY' ... PY`, or a file in the builder's scratchpad; paste its text into `## Build`; it is not committed). It reads the file, `json.loads` it with an `object_pairs_hook` that rejects duplicate keys, aborts if `permissions` already exists, and inserts the block as text before the final `}`: `text.rstrip()[:-1].rstrip() + ',\n  "permissions": ' + json.dumps(PERMISSIONS, indent=2)` with every line after the first indented two more spaces, then `'\n}\n'`. It re-parses, asserts `new["hooks"] == old["hooks"]`, `list(new) == ["hooks", "permissions"]` and `new["permissions"] == PERMISSIONS`, writes `.claude/settings.json.tmp` and `os.replace`s it (Claude Code reloads settings on save; a half-written file is a Settings Error that drops the hooks for the running session). Text insertion, not `json.dump` of the whole document, keeps the other session's hook lines byte-identical: the diff is added lines plus one changed line, `  }` to `  },` (`git diff --numstat` = N added, 1 deleted). PERMISSIONS, one rule per line, in this order: `allow` = `Bash(cargo *)`, `Bash(rustup *)`, `Bash(pnpm *)`, `Bash(corepack *)`, `Bash(node *)`, `Bash(npx playwright *)`, `Bash(docker *)`, `Bash(docker compose *)`, `Bash(git add *)`, `Bash(git commit *)`, `Bash(git push *)`, `Bash(git rebase *)`, `Bash(git worktree *)`, `Bash(git switch *)`, `Bash(gh pr *)`, `Bash(tofu fmt *)`, `Bash(tofu validate *)`, `Bash(tofu plan *)`, `Bash(tools/monitor/*)`, `Bash(python3 tools/monitor/*)`, `Bash(bash tools/doctor.sh)`, `Bash(aws sts get-caller-identity)` (22); `deny` = `Bash(tofu apply *)`, `Bash(tofu destroy *)`, `Bash(aws *)`, `Bash(git push --force*)`, `Read(.env.local)`, `Read(.env.*.local)` (6). No other key (`ask`, `$schema`, `defaultMode`): the spec says nothing else.
2. `docs/ops/permissions.md` (new, about 40 lines): where the file lives and whom it binds (committed project settings, merged with `~/.claude/settings.json` and `.claude/settings.local.json`; allow rules wait for workspace trust; reloaded on save); the precedence quote above; a table with one row per allow rule and one per deny rule, each rule verbatim in backticks (the test looks for them) with one line on what it lets a station run or stops; an `aws` paragraph: the `Bash(aws sts get-caller-identity)` allow records the intended exception but is inert under deny-first precedence, so agents cannot run it either and the user runs it in a terminal; the rule that production credentials never reach station agents, linking `docs/ops/secrets.md` (compose defaults, record/replay fixtures, OIDC role in CI, no long-lived keys); the limits the docs state: a Bash rule matches the command text only (`/usr/bin/aws`, `sh -c '...'`, `git -C . push` escape it), `Bash(git push --force*)` stops only commands that begin with `git push --force` (not `git push -f` or `git push origin main --force`), the Read denies do not cover `grep -r` or scripts that open the file themselves; what is not here: hooks (P0-10, `tools/monitor/README.md`), personal rules belong in `.claude/settings.local.json`.

Risks and how to check:
- Deny-first precedence makes the `aws sts get-caller-identity` allow inert; the spec's "except" is not expressible with rules, `ask` (also evaluated before allow) or a PreToolUse hook (cannot override a deny). Kept as the spec and the foreman asked; permissions.md says so; if the foreman amends the spec to drop the entry, drop it from the test's allow list too.
- `Bash(git push --force*)` matches the text before the first `*` as written: `git push -f ...` and `git push origin main --force` are not denied. The foreman may add `Bash(git push -f *)`, `Bash(git push * --force*)` and `Bash(git push * -f*)` by spec amendment; not added here.
- Live reload: an invalid intermediate file disables the hooks of the running session (monitor traces stop); step 1 validates before an atomic replace; check that the builder's own tool calls keep appearing as `agent.activity`.
- The other session owns the hooks: the builder re-reads the file immediately before writing, changes one byte of the hooks block (the comma) and nothing under `tools/monitor/`; `git diff --numstat` is the check.
- A rule typo surfaces only as a startup Settings Warning: the shape regex in the test and `claude doctor` catch it. `Bash(docker compose *)` is subsumed by `Bash(docker *)` and `Bash(bash tools/doctor.sh)` is an exact match (`--root` prompts): both as specified.
- Scope: project allow rules are ignored in an untrusted folder or a `claude -p` run without trust (stderr warning); the Read denies anchor at the session's working directory (repository root or worktree), which is where the factory runs.

Leave alone: the hook entries and `tools/monitor/*`; `~/.claude/settings.json`; `.claude/settings.local.json` (absent; do not create it); `.gitignore` (already lists `.env.local` and `.env.*.local`); `docs/ops/secrets.md` (linked only); `tools/doctor.sh` and `tools/test/doctor.test.sh`; the other sections of this card.
