# P0-06.2 Claude Code command allowlist for the factory

## Spec

What: `.claude/settings.json` with the permission allowlist the factory's station agents need, so routine commands do not prompt.
Acceptance criteria:
1. `.claude/settings.json` is valid JSON with `permissions.allow` entries for: `Bash(cargo *)`, `Bash(rustup *)`, `Bash(pnpm *)`, `Bash(corepack *)`, `Bash(node *)`, `Bash(npx playwright *)`, `Bash(docker *)`, `Bash(docker compose *)`, `Bash(git add *)`, `Bash(git commit *)`, `Bash(git push *)`, `Bash(git rebase *)`, `Bash(git worktree *)`, `Bash(git switch *)`, `Bash(gh pr *)`, `Bash(tofu fmt *)`, `Bash(tofu validate *)`, `Bash(tofu plan *)`, `Bash(tools/monitor/*)`, `Bash(python3 tools/monitor/*)`, `Bash(bash tools/doctor.sh)`; and `permissions.deny` for `Bash(tofu apply *)`, `Bash(tofu destroy *)`, `Bash(aws *)` except `Bash(aws sts get-caller-identity)`, `Bash(git push --force*)`, `Read(.env.local)`, `Read(.env.*.local)`.
2. `docs/ops/permissions.md` explains each allow and deny in one line and the rule that production credentials never reach station agents (docs/ops/secrets.md).
3. A test (`python3 -c` or a tiny script in tools/) validates the JSON and asserts the deny list contains the four destructive entries.
Out of scope: changing the user's global ~/.claude settings.
Files: .claude/settings.json, docs/ops/permissions.md.
