# P0-08.1 Card tooling: manual gates and worktree-safe card.py and log.sh

## Spec

What: the card tool learns manual gates and works from a lane's worktree. Why: the P0-08 row (`docs/plan/roadmap.md` E2 and E1): "`manualGates:` in the card frontmatter; the foreman refuses ship while any is unticked", and "absolute-path card.py and log.sh" so that agents in a worktree report to one place.
Acceptance criteria:
1. Manual gates: a card may list gates in its frontmatter (`manualGates:`); each gate is open or ticked, with who ticked it and when recorded in the card. `card.py move <id> ship` (any status) exits non-zero and names every open gate, and moves nothing; with every gate ticked it moves as today. A command ticks a gate (`card.py gate <id> <gate> --by <who> [--evidence <path or url>]`), and `card.py list` shows the count of open gates of a card that has any. A card without gates behaves exactly as before (the existing tests of `tools/monitor/test/card.test.py` pass unchanged).
2. Worktree-safe: run by absolute path from a linked git worktree of this repository, `tools/monitor/card.py` reads and writes the card files of that worktree (its branch), and `tools/monitor/card.py` and `tools/monitor/log.sh` write their events and traces to `.bridle/progress` of the main checkout, never into the worktree. Run from the main checkout, both behave as today. The rule for finding the main checkout is stated in the files' headers and in `factory/README.md` in one sentence.
3. `card.py new --estimate`: a test holds that the value reaches the card's frontmatter and the printed `tasks/<id>` op.
4. Tests in `tools/monitor/test/card.test.py` (and a shell or python case that creates a real linked worktree in a temporary clone) cover criteria 1 to 3, each with a failing-case assertion; `pnpm check` stays 7/7.
Files: `tools/monitor/card.py`, `tools/monitor/log.sh`, `tools/monitor/test/card.test.py` (and one new test file if the worktree case needs it), `factory/README.md` (one sentence), `.claude/skills/factory/SKILL.md` only if a command's usage line changes.
Test command for `## Test`: `python3 tools/monitor/test/card.test.py` (plus the worktree test file if one is added, named in `## Test`).

Out of scope for every P0-08 sub-card: product code (`apps`, `packages`, `crates`), `tools/agent-hq/`, and the monitor's page and viewer beyond what an acceptance criterion names. Process notes from 2026-11-17 that apply here: an absolute claim ("every", "all", "none", "only") in a shipped document or comment needs a test or a command that holds it; a station's verdict is FAIL only for an unmet acceptance criterion, a failing command, a false statement in a shipped file or a real defect, and everything else is an advisory; negative proofs and experiments run in a scratch copy or behind a backup checked with `cmp`.

Plan accepted (foreman, 2026-11-17), with these rulings:
1. `tools/monitor/trace-hook.sh` joins the card's files: criterion 2 says "traces", and a session started in a worktree would otherwise write them where no mirror reads.
2. "Run by absolute path from a linked worktree" means the worktree's own copy of the script: cards are read and written in the checkout that holds the script, events and traces go to the main checkout.
3. The gate format stays the one-line `manualGates: [Open gate, [x] Ticked gate]` already used by P0-06.3; a block list is refused with exit 1 instead of being dropped at the next move.
4. `tools/monitor/README.md` lines 57 to 58 are corrected in this card (the Spec's file list did not name the file).
5. Not this card: the unlocked `seq` of two sessions appending to one worker's JSONL (the race exists today); it is recorded at ship for P0-08.2 or P0-08.4 to decide. `log.sh` and `trace-hook.sh` serve every running session while they are edited: the builder edits each in one write and checks the hook still traces right after.

Owner's decision (2026-11-17), after the card was blocked by a second failure at the test station: one more build loop, as the foreman recommended ("lets go for the option you recommend"). The loop: an argument that is not valid UTF-8 is refused before any write, and a card file is written through a temporary file and a rename so that a failed write cannot empty a card. For the stations after it, the foreman's ruling the owner accepted with that recommendation: the four acceptance criteria were met at the first test pass; a further unusual-input case fails the card only if it lets a card past a gate or destroys or corrupts a card file, and anything else is recorded for a later P0-08 sub-card.

## Plan

Decisions (each checked against the files or prototyped in a scratch repository, since removed):
- Gate format: unchanged from the one in use. `manualGates: [Open gate, [x] Ticked gate]` on one frontmatter line; an entry starting with `[x] ` (or `[X] `) is ticked, any other is open (a leading `[ ] ` is read as open and not part of the name). `parse`/`dump` already round-trip it (P0-06.3 line 19, the only card under `factory/cards` with gates, both ticked by hand, has survived moves), and `tools/test/ci.test.sh`, `tools/test/github.test.sh`, `docs/ops/github.md` and SKILL.md pin exactly this shape. A name holds no comma, `]`, `"` or newline.
- Who and when: one `history` line per tick, in the existing five-field shape, `<ts> <station> <status> <who> "gate ticked: <name>"` or `"gate ticked: <name>; evidence: <e>"` (station and status are the card's current ones, unchanged by the tick). No new frontmatter key, so nothing else that reads cards changes. A gate ticked by hand (P0-06.3) reads as ticked with no record.
- A block list (`manualGates:` followed by `  - x` lines) is today silently dropped at the next `move`: `parse` must refuse it (exit 1, "write it on one line: manualGates: [a, b]"), as must a `manualGates:` value that is not a `[...]` list. No card has either form today.
- Commands and exit codes (0 ok; 1 any other error, as today's `SystemExit` text; 2 argparse usage; 3 open gates, used by nothing else):
  - `card.py gates <id>`: stdout, one line per gate, `open    <name>` or `ticked  <name>  (<who> <ts>[, evidence <e>])` or `ticked  <name>  (no record)`; `no manual gates` for a card without any. Exit 3 when at least one is open, else 0. Writes nothing, no event. This is the check P0-08.3's ship.sh calls.
  - `card.py gate <id> <gate> --by <who> [--evidence <path or url>]`: `<gate>` is the exact name or its 1-based position. Ticks the entry, appends the history line, sets `updated`; prints `ticked: <name>`; no monitor event. Already ticked: exit 0, prints `already ticked: <name>`, file bytes unchanged. Unknown gate or card without gates: exit 1 listing the names. `--by` empty or with whitespace: exit 1.
  - `card.py move <id> ship` (any `--status`): with an open gate, exit 3, stderr `card.py move: <id> has <n> open manual gate(s): <a>; <b>` plus the `card.py gate` hint; the card bytes are unchanged and no event is written. Other stations are not checked.
  - `card.py list`: a card with gates gets the suffix `  [gates: <open> open of <total>]` after its title; other lines byte-identical to today. `status` (the board) does not change.
- Two roots. Cards: the checkout that holds the script (today's `ROOT`), so a lane calls its own worktree's `tools/monitor/card.py` by absolute path and `list`, `show`, `new`, `move`, `gate`, `status` and `status --write FILE` read and write that worktree's cards and the FILE given. Events: the main checkout, by this rule (the sentence for the headers and `factory/README.md`): "The main checkout is the directory in `BRIDLE_MAIN_ROOT` when that is set; otherwise, when the checkout holding the script is a linked git worktree whose common git directory is `<dir>/.git`, it is `<dir>`; in every other case it is the checkout holding the script." Test: `git -C <ROOT> rev-parse --path-format=absolute --git-dir --git-common-dir --show-toplevel` (with `GIT_DIR` and `GIT_WORK_TREE` unset); linked means the first two differ; also required: basename of the second is `.git` and the third equals `pwd -P` of ROOT. Prototype results: main checkout, no git repository, git failing, a submodule, a worktree of a submodule, a worktree of a bare clone and a copy nested inside another repository's worktree all give the script's checkout; a linked worktree gives the main checkout, also when reached through the `/tmp` symlink; `BRIDLE_MAIN_ROOT` that is not a directory exits 1 and writes nothing.
- The rule lives in `log.sh` only (it stays standalone); `card.py` writes events only through its own checkout's `log.sh`, so `card.py` makes no git call and `test_status_source_has_no_side_channels` and `test_isolated_root_writes_nothing_else` hold as written. `log.sh --main-root` prints the main checkout and exits (for trace-hook.sh, and for lane.sh and ship.sh later).
