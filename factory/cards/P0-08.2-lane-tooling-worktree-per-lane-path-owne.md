# P0-08.2 Lane tooling: worktree per lane, path ownership, lane check

## Spec

What: the tooling of a lane: its worktree and branch, which paths it owns, and a check that a card stays inside it. Why: the P0-08 row and `docs/plan/roadmap.md` E1: "one worktree, branch `lane/<name>` and foreman session per lane (`core` = crates, packs, datasets, packages/schema and the root workspace files; `web` = apps/web, packages/ui, api-core, api-client, engine-protocol; `platform` = apps/worker, judge, system, packages/grader, infra, .github), at most one card running per lane"; the owner's decision of 2026-11-17: each lane owns its files and one lane owns the root files.
Acceptance criteria:
1. `tools/factory/lane.sh new <name>` creates a linked worktree outside the main checkout's tracked tree on a new branch `lane/<name>` from `origin/main`, and prints its path; `list` shows each lane with its path, branch and whether a card is running in it; `remove <name>` removes the worktree and the branch only when the branch is merged or has no commits of its own, and refuses otherwise with the reason. A second `new` of the same name is refused.
2. `factory/lanes.json` maps path patterns to the lanes core, web and platform as E1 lists them; the root workspace files (the lockfiles, `package.json`, `pnpm-workspace.yaml`, `turbo.json`, `Cargo.toml`, the `Dockerfile`, `tools/toolchain.json` and the files that mirror its pins) belong to one lane, core; paths E1 does not name (`docs/`, `factory/`, `tools/`, `e2e/`, `packages/i18n`, `packages/units`) are each assigned by this card, with the reason in the file's comment field. A test fails when a tracked path of the repository matches no lane or two lanes.
3. `tools/factory/lane-check.sh <lane> [<base>]` lists the files a branch changes against its base (default `origin/main`) and exits non-zero, naming each file, when one belongs to another lane; a card's own file under `factory/cards/` is allowed in any lane.
4. "At most one card running per lane": the lane a card runs in is recorded on the card (frontmatter `lane:`), and starting a second card in a lane whose card is at a station from plan to review is refused by the tool that records it; how (in `card.py move` or in `lane.sh`) is the planner's decision, stated with its reason.
5. `tools/test/lanes.test.sh` (with "card P0-08.2" in its second line) proves criteria 1 to 4 on a temporary clone, never on this checkout's worktrees, and leaves no worktree or branch behind; `pnpm check` stays 7/7 and `bash tools/test/docs.test.sh` stays green (its `readme` case holds the label of `tools/test`: reword the label in this card's commit if it no longer fits).
Files: `tools/factory/lane.sh`, `tools/factory/lane-check.sh`, `factory/lanes.json`, `tools/test/lanes.test.sh`, `tools/monitor/card.py` only if criterion 4 goes there, `README.md` and `tools/test/docs.test.sh` only for the `tools/test` label.

Out of scope for every P0-08 sub-card: product code (`apps`, `packages`, `crates`), `tools/agent-hq/`, and the monitor's page and viewer beyond what an acceptance criterion names. Process notes from 2026-11-17 that apply here: an absolute claim ("every", "all", "none", "only") in a shipped document or comment needs a test or a command that holds it; a station's verdict is FAIL only for an unmet acceptance criterion, a failing command, a false statement in a shipped file or a real defect, and everything else is an advisory; negative proofs and experiments run in a scratch copy or behind a backup checked with `cmp`.
