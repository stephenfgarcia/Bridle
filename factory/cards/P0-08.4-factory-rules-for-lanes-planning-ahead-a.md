# P0-08.4 Factory rules for lanes, planning ahead and tests alongside the build

## Spec

What: the factory's rules for parallel work, and the rehearsal that closes the row. Why: the P0-08 row: "line.md and SKILL.md updated"; the owner's decision of 2026-11-17 (`docs/decisions/log.md`; the note in card P0-08's Spec).
Acceptance criteria:
1. `factory/line.md`, `factory/README.md`, `.claude/skills/factory/SKILL.md` and the four station agents under `.claude/agents/` describe: the lane procedure (start a lane, run a card in it, ship by pull request with `tools/factory/ship.sh`, the `Cards: <id> shipped` step on `main`, remove the lane); which lane owns which paths (`factory/lanes.json`) and that a card needing another lane's files splits that change into a sub-card in that lane which ships first; one watch for all lanes; what stays serial (merges; the work-package spec station; anything editing `docs/plan/progress.md`).
2. Planning ahead: the planner may plan the next two or three cards while a card builds; the builder's first step is to re-check the plan against current `main` (the files and line facts the plan names) and to send it back when they have moved; the documents say who starts the planner and where the early plan is written.
3. Tests alongside the build: the tester may write the card's test file from the Spec's acceptance criteria while the builder builds, without reading the builder's code; the full test run still follows the build; the documents say how the two agents avoid editing the same file.
4. The station rules learned on 2026-11-17 are in `factory/line.md` and the agents: the verdict standard; an absolute claim needs a test or a command that holds it; after a rework that changes documents only, the test and review stations check the change and what it touches; negative proofs run in a scratch copy or behind a backup checked with `cmp`; card sections stay short (tables and result lines). The review fan-out by workflow is named as for large or risky cards only, at the owner's request.
5. Rehearsal (the row's acceptance criteria 1 and 2): two lanes, each running one small documents-only card through the line at the same time from its own worktree, each shipped by pull request, one merge after the other, with the monitor showing both cards; `## Ship` records both pull requests and what the rehearsal showed, including anything that had to be done by hand.
6. `bash tools/test/docs.test.sh` stays green with its `factory-docs` case extended to hold the new rules' key sentences; `pnpm check` stays 7/7.
Files: `factory/line.md`, `factory/README.md`, `.claude/skills/factory/SKILL.md`, `.claude/agents/factory-*.md`, `CLAUDE.md` if its several-sessions sentence changes, `tools/test/docs.test.sh`, two rehearsal cards under `factory/cards/`.
This card closes the P0-08 row; after it the owner approves the acceptance criteria and splits of P1-01, P2-01 and P4-06 in one sitting.

Out of scope for every P0-08 sub-card: product code (`apps`, `packages`, `crates`), `tools/agent-hq/`, and the monitor's page and viewer beyond what an acceptance criterion names. Process notes from 2026-11-17 that apply here: an absolute claim ("every", "all", "none", "only") in a shipped document or comment needs a test or a command that holds it; a station's verdict is FAIL only for an unmet acceptance criterion, a failing command, a false statement in a shipped file or a real defect, and everything else is an advisory; negative proofs and experiments run in a scratch copy or behind a backup checked with `cmp`.
