# PX-01.1 Model types and validation

## Spec

Pitch card S1 of `docs/plan/pitch-plan.md` (core lane; packages/model and packages/solver), approved by the owner with the plan on 2026-11-18. What: Model types and validation: nodes, members, sections, materials, supports, loads, load cases; JSON format. Why: the showcase of 2026-12-16 for the owner's pitch and thesis defense on 2027-01-01. Review station: no (the pitch process: one agent builds and tests; `pnpm check` green before the commit). The foreman writes this card's acceptance criteria here before its build starts.

Acceptance criteria (foreman, 2026-11-18):
1. A new workspace package `packages/model` (name `@bridle/model`, TypeScript, built and tested the way `packages/i18n` is) exports the types of a structural model: `Node` (id, x, y, z), `Member` (id, start node, end node, section id, material id, kind `frame` or `truss`, roll angle, end releases), `Section` (id, name, A, Iy, Iz, J, and the depths the stress check needs), `Material` (id, name, E, G, fy, density), `Support` (node id, six restraint flags), `NodalLoad`, `MemberUniformLoad` and `MemberPointLoad` (each with a load case id and a global or local direction), `LoadCase`, and `Model` (a `version`, `units`, and the lists above).
2. Conventions, stated in the package's README and in the type comments: the global Z axis is up and gravity acts along minus Z; the model stores forces in kN and lengths in m (so moments are kN·m and E is kN/m²); the documents name which display units the interface uses (MPa for stress, mm for deflection), with the conversions taken from `packages/units` where it has them.
3. `validateModel(model)` returns a list of issues, each with a code, a message key and the ids it concerns, and returns an empty list for a valid model. It reports at least: a duplicate id, a member that names a missing node, section or material, a member of zero length, a non-positive A, I, J, E or G, a support or load that names a missing node, member or load case, a point load position outside the member, and a model with no support.
4. `parseModel(json)` and `serializeModel(model)` round-trip: a serialized model parses to an equal model, and a JSON text of the wrong shape is refused with an issue list instead of an exception.
5. Three fixture models are exported for later cards and tests: a simply supported beam, a portal frame and a small truss, each valid by criterion 3.
6. Unit tests cover each issue code of criterion 3 with one failing model, the round trip, and the three fixtures; `pnpm check` is 7/7; `factory/lanes.json` already gives `packages/model/` to core.
Files: `packages/model/` (new), `pnpm-lock.yaml` and the workspace files only as a new package needs. Out of scope: any analysis (S2 onwards), any user interface, load combinations.
