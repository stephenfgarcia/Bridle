# PX-02.4 Node and member tools

## Spec

Pitch card W4 of `docs/plan/pitch-plan.md` (web lane; apps/web), approved by the owner with the plan on 2026-11-18. What: Tools: add, move and delete a node; draw a member; snap to grid. Why: the showcase of 2026-12-16 for the owner's pitch and thesis defense on 2027-01-01. Review station: no (the pitch process: one agent builds and tests; `pnpm check` green before the commit). The foreman writes this card's acceptance criteria here before its build starts.

Acceptance criteria (foreman, 2026-11-18):
1. A tool palette in the workspace with the tools Select (the default), Node and Member; the active tool is visibly marked and announced to assistive technology; Escape returns to Select and cancels a member in progress; each tool has a one-key shortcut shown in its tooltip.
2. Work plane and snap: a control chooses the work plane, the vertical plane X-Z at a chosen Y (the default, Y = 0, for frames drawn in elevation) or the horizontal plane X-Y at a chosen Z; a control chooses the snap step (0.1, 0.25, 0.5 or 1 m; default 0.5 m). With the Node or Member tool active, a marker follows the pointer at the snapped point of the work plane and a readout shows its X, Y, Z in metres.
3. Node tool: a click places a node at the snapped point (one undo step). A click on a point that already has a node selects that node instead of placing a second one.
4. Member tool: a click on a node, or on an empty point (which places a node there), starts a member; a preview line follows the pointer; the next click ends the member at a node or a new point and starts the next member from there, until Escape or a double click. Each member, with a node it had to create, is one undo step. The new member takes the first section and the first material of the model. What the store refuses (the same node twice, a second member between the same two nodes) leaves the model unchanged and shows a short message.
5. Select tool: dragging a selected node moves it on the work plane through its current position, snapped, as one undo step on release; the side panel shows editable X, Y, Z fields for the selected node, applied on Enter or on leaving the field. The Delete and Backspace keys and a Delete button remove the selected node or member (with what depends on it) as one undo step, except while the focus is in a text field.
6. "New model" starts an empty model that already has one default section and one default material (the ones of the fixtures), after a confirmation if the present model has changes; the example-model switch keeps working.
7. A drag still orbits the camera with every tool (a press and release more than 2 px apart is a drag, as in W2), and a click acts as the tool says; clicking empty space with the Select tool clears the selection.
8. Tests: unit tests of the pure parts (the ray to work-plane point, the snap, the tool state machine of the Member tool including Escape and the refusals); one browser test that starts a new model, places two nodes and a member with pointer events on the canvas in the Front view, reads the counts 2 and 1 from the side panel, and undoes the member; `pnpm check` is 7/7; `tools/test/web.test.sh` and `tools/test/i18n.test.sh` are kept passing (their file list and smoke counts). Two screenshots at 1280 by 720 for the foreman: the Member tool in use with the preview line, and a small frame drawn by hand.
9. Every user-facing string is in the catalog of `packages/i18n`. If `main` has gained the issue code `non-finite-value` in `packages/model` by the time this card builds, its message is added to the catalog and to `issueMessages.ts`.
Files: `apps/web/`, `e2e/`, `packages/i18n/messages/`, `tools/test/web.test.sh`, `tools/test/i18n.test.sh`, `docs/ops/local-dev.md` if a sentence there becomes untrue. Out of scope: supports and loads (W5), the property panel for members (W6), the table editor (W7), analysis and results.

## Build

What was built, in layers. The pure parts are in `apps/web/src/components/tools/` and import no React, no zustand and no three.js: `workPlane.ts` (the geometry) and `drawTools.ts` (the tools' rules). `toolStore.ts` holds the tools' state, `toolActions.ts` runs the rules on the stores, and `viewport/ToolLayer.tsx` is the only file that turns pointer events and the three.js camera into calls of them.

By acceptance criterion:

1. Palette: `ToolPalette.tsx`, at the top left of the viewport, before the work-plane and snap controls and the camera buttons (Fit, 3D, Front, Top). Three buttons in a `role="toolbar"` named "Tools": Select (the default), Node, Member. The active one is filled with the accent colour and has `aria-pressed="true"`; the line at the bottom left of the viewport says what the active tool does and is a `role="status"` region, so its text changes with the tool. Keys: V, N, M (`toolKeys.ts`), named in each button's tooltip (`title`, as "Member (M)") and in `aria-keyshortcuts`. Escape makes Select the active tool and ends a member in progress. The keys do nothing with Ctrl, Cmd or Alt; a letter does nothing in a text field or on a `<select>`.
2. Work plane and snap: a select "X-Z (elevation)" / "X-Y (plan)" (its accessible name and tooltip are "Work plane"), a field "at Y (m)" or "at Z (m)" for the plane's position (applied on Enter or on leaving the field), and a select "Snap" with 0.1, 0.25, 0.5 and 1 m. Defaults: X-Z at Y = 0, 0.5 m. Choosing the other kind of plane puts it at 0. The plane is drawn as a grid in the selection colour with a 6 % tint over its area (1 m cells, a major line every 5 m; these lines are not the snap grid). With the Node or Member tool a marker (a ring with a dot, 22 px) follows the pointer at the snapped point, and a readout at the bottom left shows "X .. Y .. Z .. m". When the pointer's ray does not meet the plane (the plane seen edge-on, as X-Z in the Top view) there is no marker and the readout's place says so.
3. Node tool: a click places a node at the marker (one undo step) and selects it. When a node is already at that point, or the pointer is within 9 px of a node on screen, the click selects that node and places nothing.
4. Member tool: the first click starts at the node under the pointer or at the marker's point, where it places a node (that node is one undo step of its own). A line follows the pointer from the start node. The next click ends the member at a node or at a new point and the next member starts there. Escape (back to Select) or a double click (the tool stays) ends the chain. A member together with a node it had to create is one undo step (`apply` with one model from `memberToolStep`). The member is added by `addMember` with its defaults: the model's first section and first material. Refusals leave the model and the undo steps as they were, keep the start node and show a message at the bottom left (`role="alert"`): the start node itself ("A member needs two different nodes."), two nodes that already have a member, a model without a section or material, anything else the commands refuse. The message goes with the next click that works, a change of tool or Escape. A double click's second click lands on the node the first one just made and is refused as "the same node"; the `dblclick` event that follows clears that message before the page is painted (checked in the scratch script: no notice after a double click).
5. Select tool: a press on the selected node (within 9 px, without Shift, Ctrl or Cmd) switches the orbit controls off until the release. After more than 2 px of movement the node's landing point follows the pointer on the plane of the work plane's kind through the node's place, snapped; the marker and a line to the other end of each of its members show it; the release moves the node as one undo step. The node's own marker stays at its old place until the release. A move onto another node is refused with the message "Another node is already at that place.". The side panel shows X, Y, Z fields for the selected node (`NumberField.tsx`: applied on Enter or on leaving the field, one undo step; a text that is not a number is dropped; Escape drops the edit; a decimal comma is read as a point). Delete: the Delete and Backspace keys, and a Delete button under the selected item, remove the selected node (with its members, their loads, its support and loads: `deleteNode`) or member (`deleteMember`) as one undo step and clear the selection; the keys do nothing in a text field.
6. "New model" (side panel, above the example switch) loads `newModel()`: `emptyModel()` with the section, the material and the load case of the fixtures (taken from `portalFrame()`). When the model has an undo step, `window.confirm` asks first. The example switch then shows a disabled entry "None (new model)" and still loads the three examples. The camera frames an 8 m by 5 m drawing area on the work plane while the model has no node, and the grids always cover that area, so they do not change size while the first nodes are placed in it.
7. Drags and clicks: a press and release more than 2 px apart is left to the orbit controls with every tool and does nothing else, except the drag of the selected node above. A click acts as the tool says. With the Select tool the nodes' and members' own handlers select as before and a click on nothing clears the selection; with the other two tools those handlers do nothing and the hover highlight shows the node the click would use.
8. Tests: see `## Test`.
9. Strings: 26 new messages (`workspace.tools.*`, `workspace.plane.*`, `workspace.snap.*`, `workspace.cursor.*`, `workspace.notice.*`, `workspace.model.new`, `.newConfirm`, `workspace.fixture.none`, `workspace.selection.delete`) and a new text for `workspace.viewport.help` (now the Select tool's line); `en-XA.json` regenerated (88 messages). Not in the catalog: the key letters V, N, M. `non-finite-value`: the lane does not have the code, and by the foreman's note during the build nothing was added for it (catalog and `issueMessages.ts` untouched for that key).

Decisions:
- Hooks for a test or a script, on the element `data-testid="viewport-surface"`: `data-tool` (`select`, `node`, `member`), `data-cursor` (the point a click would use, or where a dragged node would land, as `x,y,z` in m, empty when there is none), `data-member-start` (the start node's id), `data-dragging` (the dragged node's id), beside `data-hover` of PX-02.2. Other test ids: `tool-palette`, `work-plane`, `work-plane-offset`, `snap-step`, `cursor-readout`, `cursor-problem`, `tool-notice` (with `data-notice`), `tool-hint`, `new-model`, `node-x`, `node-y`, `node-z`, `delete-selection`.
- The pointer layer listens on the window: `pointerdown` in the capture phase, so the orbit controls are switched off before they see a press on the selected node; `pointermove`, `pointerup` and `pointercancel`, so a drag that leaves the canvas still ends. It does its own node pick (the nodes projected to the screen, nearest within 9 px) and does not depend on the order of its listeners and react-three-fiber's.
- No React state is set per pointer move. The tool store's cursor changes only when the snapped point or its node changes; the marker and the preview lines are three.js objects moved through refs by a subscription to the two stores, followed by `invalidate()`. The readout and the surface's attributes re-render on a cursor change; the scene (`ModelScene`) does not subscribe to the cursor.
- The preview line is a `LineSegments2` of `three/examples/jsm/lines`, 3 px wide. Its buffer is written in place while the number of segments stays the same and the geometry is replaced when it changes: the renderer keeps the instance count a geometry was first drawn with (a second drag line was not drawn before this).
- A node within 9 px of the pointer wins over the grid point, also when the node is off the work plane, so an existing node can be used from any view.
- The grids are sized for the model's box together with the 8 m by 5 m drawing area. For the three fixtures this makes the ground grid a little larger than in PX-02.2 (the portal frame: X from -5 to 15 instead of -5 to 10).
- `newModel()` also holds the fixtures' load case `lc1`, beyond the criterion's section and material: `addNodalLoad` and the member loads refuse without a load case, which W5 would otherwise meet first.
- `window.confirm` for "New model": the browser's own dialog, no dialog component yet.

Deviations and limits:
- Out of the criteria and not done: Escape does not cancel a node drag in progress (releasing on the start place does); a press on a node that is not selected orbits, it does not drag; no touch-specific handling; no keyboard way to place a point; the toolbar wraps to a second row when its texts are longer (the pseudo-locale), where it can cover a node at the top of a fitted model.
- A point under the toolbar, the Undo and Redo buttons or the axis indicator's corner cannot be clicked while they cover it: orbit, pan or zoom first.
- A first click of the Member tool on an empty point leaves a node if the chain is ended at once (one Undo removes it).
- `bash tools/factory/lane-check.sh web main` was not run; `docs/ops/local-dev.md`, `tools/test/web.test.sh` and `tools/test/i18n.test.sh` are outside `apps/web` and in this card's Files list.
- No defect found in `packages/model` or `packages/solver`; neither was edited.

For W5 (support and load tools): add the tool to `Tool` and `TOOLS` in `toolStore.ts`, a key in `TOOL_KEYS`, a name in `TOOL_NAME` (`ToolPalette.tsx`) and a hint in `HINT` (`ToolStatus.tsx`); the records are total over `Tool`, so the compiler lists the places. `ToolLayer.tsx` computes the cursor for every tool but Select and calls `toolClick(cursor)`: a support or load tool needs a branch there only (`cursor.nodeId` is the node a click means, or `null`). There is no pick of a member by the tool layer yet: the members' own handlers in `ModelScene.tsx` are switched off outside the Select tool (`selecting()`), so a member-load tool must either act on the selection or let those handlers run for it. Use `run()` in `toolActions.ts` for one undo step from a pure step, and `ToolNotice` with `NOTICE_MESSAGE` for a refusal's message. A new model has the load case `lc1`.
For W6 (property panel): the selected node's fields are `NodeCoordinates` in `SidePanel.tsx`, built on `NumberField` (value, `onCommit`, applied on Enter or blur); `deleteSelection()` and the Delete button are there already and work for a member. `selectionRows` still gives a member's read-only rows. Delete and Backspace are ignored in text fields and letters also on a `<select>` (`toolKeyAction`), so new fields need nothing for that.
