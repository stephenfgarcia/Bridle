# PX-03.2 Task format and three seeded tasks

## Spec

Pitch card T2 of `docs/plan/pitch-plan.md` (tasks and grading), approved by the owner with the plan on 2026-11-18. What: Task format and three seeded tasks with rubrics and reference models. Why: the showcase of 2026-12-16 for the owner's pitch and thesis defense on 2027-01-01. Review station: no (the pitch process: one agent builds and tests; `pnpm check` green before the commit). The foreman writes this card's acceptance criteria here before its build starts.

Foreman's note (2026-11-18): this card runs ahead of its listed dependency (the illustrative checks of card S8) in a third lane, platform, because it shares no files with the cards running in core and web, and because the owner must read the three task briefs by 2026-11-28. What depends on S8 is marked below and left for card T6.

Acceptance criteria (foreman, 2026-11-18):
1. A new workspace package `packages/tasks` (`@bridle/tasks`, TypeScript, set up like `packages/model`, depending on `@bridle/model` and `@bridle/solver` by `workspace:*`) exports the task format: a `Task` has an id, a title, a level (introductory, intermediate), a brief in plain paragraphs, a list of learning outcomes, a starting model (a `Model` the learner begins from; which of its parts are fixed is a list of ids), a list of required answers (each with an id, a prompt, a quantity kind such as force, moment, displacement or ratio, a unit for display, and a tolerance as a relative and an absolute part), an optional list of design requirements stated in words with a machine-readable limit (for example a deflection limit of span over 360), a rubric (three to five criteria, each with a name, a weight, and three or four level descriptions from "not shown" to "exemplary"), and a reference model.
2. `validateTask(task)` reports issues the same way `validateModel` does (duplicate ids, weights that do not sum to 1, a fixed id that the starting model lacks, a starting or reference model that `validateModel` rejects, a tolerance that is not positive).
3. Three tasks are exported, written for third- or fourth-year structural engineering students, in SI units, with realistic numbers: (a) "Simply supported beam": a steel beam of a given span under a uniform load; the learner models it, restrains it properly, and reports the reactions, the maximum bending moment and the mid-span deflection; (b) "Portal frame under wind and gravity": a fixed-base steel portal with a beam uniform load and a lateral load; the learner reports the base reactions and moments and the sway, and judges the sway against a drift limit of height over 300; (c) "Choose the beam": a floor beam where the learner must choose a section from a short list so that the deflection is within span over 360 under the given load, and justify the choice; the stress check part of this task is written in the brief but its reference value waits for card S8 and T6 (say so in the task's data with an explicit marker, not a made-up number).
4. Reference answers are not typed in: a function computes each required answer of a task from its reference model with `solve` of `@bridle/solver` (reactions, end moments, displacements at nodes; the reference models have a node where a value is needed, for example at mid-span), and a test compares each computed answer of tasks (a) and (b) with the closed-form value (wL/2, wL²/8, 5wL⁴/384EI; for the portal an equilibrium check and the values frozen from the solver with the date). The section list of task (c) uses the generic sections that will become the catalog of card S8: define them here with A, Iy, Iz, J and depths from standard formulas for rolled-I-like shapes, named generically (for example "I 300x150"), not as licensed catalog designations.
5. A document for the owner, `docs/content/tasks.md`, generated by a script of the package (`pnpm --filter @bridle/tasks docs`) from the same data, shows for each task the title, level, brief, what the learner must report, the design requirements, the rubric as a table, and the reference answers with units; a test fails when the document is out of date. `factory/lanes.json` gives `docs/` to core: this card names that one file outside its lane.
6. Unit tests cover `validateTask` (one failing task per issue), the three tasks being valid, the reference answers, and the document being current; `pnpm check` is 7/7; `bash tools/test/lanes.test.sh` passes (the path `packages/tasks/` is already in the map).
Outside the lane: `docs/content/tasks.md` (the generated document for the owner)
Files: `packages/tasks/` (new), `docs/content/tasks.md` (new), `pnpm-lock.yaml`. Out of scope: any interface (T3, T4), submissions (T5), comparing a learner's answers (T6), the AI feedback (T7), the stress check reference of task (c).

**The engineering choices, with numbers**

Steel for all three: E = 210 000 MPa, G = 81 000 MPa, fy = 355 MPa (the material of the model fixtures). All loads are service values in one load case `LC1`, and each brief says the load includes self-weight. Every structure lies in the X-Z plane; the beams hold `ux, uy, uz, rx` at A and `uy, uz` at B.

Generic I-sections (three rectangles, no fillets; dimensions h, b, tw, tf in mm in `sections.ts`): A = 2·b·tf + (h − 2tf)·tw; Iy = [b·h³ − (b − tw)(h − 2tf)³]/12; Iz = [2·tf·b³ + (h − 2tf)·tw³]/12; J = [2·b·tf³ + (h − tf)·tw³]/3 (thin-walled). Eleven shapes from I 200x100 to I 600x220. The ones the tasks use:

- **(a) Simply supported beam** (introductory): span 6 m, 15 kN/m, I 300x150. Starting model: nodes A (0), C (3 m), B (6 m), the section, the steel, the load case; the learner draws members A-C and C-B, adds the supports and the load. Four answers: reactions at A and B (45 kN each), maximum moment (67.5 kN·m), mid-span deflection (14.79 mm, span/406). Bending stress by M/W would be about 124 MPa, so the given beam is a sensible one. Rubric: Model and supports 0.30, Loads 0.20, Reported results 0.30, Engineering judgement and justification 0.20.
- **(b) Portal frame under wind and gravity** (intermediate): 8 m wide, 5 m high, columns I 300x150, beam I 400x180, 30 kN/m on the beam and 20 kN along +X at the top of the left column (node B), both bases fixed. Starting model: the four nodes and three members, fixed; the learner adds the supports and the loads. Eight answers: horizontal reactions, signed (+15.61 kN at A, −35.61 kN at D), vertical reactions (114.30 and 125.70 kN), base moments as magnitudes (15.36 and 69.78 kN·m), sway at B (7.78 mm), sway over the limit (0.467; the limit is 5 m/300 = 16.67 mm, met). Rubric: Model and supports 0.20, Loads 0.20, Reported results 0.30, Drift judgement and justification 0.30.
  Why 30 kN/m against 20 kN: at the windward base A the horizontal reaction and the moment are each a gravity part minus a wind part. My first choice (25 kN/m, 30 kN, columns I 360x170) gave a base moment at A of 2.1 kN·m, a number a 1 percent tolerance cannot judge and that the closed form misses by 25 percent. The loads were chosen so that both differences stay well away from zero.
- **(c) Choose the beam** (intermediate): span 7 m, 25 kN/m, limit span/360 = 19.44 mm, six sections from I 300x150 to I 500x200. Everything is given and fixed; the learner chooses one section for both members (`sectionChoice`). I 300x150, I 330x160 and I 360x170 exceed the limit (45.68, 32.02, 23.56 mm); I 400x180, I 450x190, I 500x200 meet it (16.44, 11.44, 8.08 mm). Reference choice: I 400x180, the lightest that passes (ratio 0.845). Answers: maximum moment 153.125 kN·m, deflection 16.44 mm, ratio 0.845, and the bending stress, whose source is the marker `{ kind: "pending", waitsFor: ["S8", "T6"], reason }`: no number for it exists anywhere in the package or the document. Rubric: Section choice 0.35, Reported results 0.20, Stress check 0.15, Justification of the choice 0.30.

**Tolerances.** Relative: 1 percent for forces, moments and the stress; 2 percent for displacements and for the two ratios (each is a displacement over its limit). Absolute: half of the last digit a learner types (0.05 kN, 0.05 kN·m, 0.05 mm, 0.005 for a ratio, 0.5 MPa), so that a correctly rounded answer never fails. Rule, stated in `types.ts` and not applied by this card: |answer − reference| ≤ max(relative × |reference|, absolute), in the display unit.

**Deviations from the Spec, and additions**

1. Criterion 5's command `pnpm --filter @bridle/tasks docs` does not run the script with pnpm 12.16.1: `docs` is a command of pnpm itself. It prints `error: the following required arguments were not provided: <PACKAGE>` and exits 2. The script is named `docs` as the Spec says and runs with `pnpm --filter @bridle/tasks run docs`; the README, the document's first note and the test's name all say `run docs`.
2. Criterion 2 lists "a starting model that `validateModel` rejects". `validateTask` reports every issue of the starting model except `no-support`: tasks (a) and (b) ask the learner to add the supports, and `validateModel` rejects a model without one. A reference model without a support is reported. If the foreman wants the criterion literally, the change is one argument in `validate.ts` plus a given support in two starting models.
3. Fields added to the format beyond criterion 1: `givens` (label and value texts for the brief's table), `justification` (the prompt of the written answer the rubrics assess), `signed` on an answer (signed value or magnitude), `basis` on a criterion (model, results, answers, justification), `sectionChoice` (members and sections of the choice in task (c)), `loadCaseId`, and a `source` on each answer (where in the solver's results its value is read). "Fixed parts" are `{ list, id }` pairs, not bare ids, because ids are unique only within one list of a `Model`.
4. `validateTask` has ten codes beyond the five the Spec names (the fifteen are in the README), for example `unit-kind-mismatch` and `missing-reference-part`.
5. The script runs under vitest (`vitest.docs.config.ts`): the workspace packages export TypeScript sources with extensionless imports, which plain `node` cannot load, and the repository has no other TypeScript runner. `@types/node` is a dev dependency for the test and the script; the exported library uses no Node API.
6. `pnpm exec biome check --write docs/content` does nothing: `biome.json` excludes `docs`. The command exits 0.

**What the tester or a reviewer must know**

- The section I 300x150 here (Iy = 8.147e-5 m⁴, from its dimensions) is not the fixture section of the same name in `packages/model` (Iy = 8.4e-5 m⁴, round values). Card S8 should take this list.
- In task (b) the solver's values differ from a hand calculation that neglects axial deformation by up to 1.7 percent (the base moment at A: 15.36 against 15.63 kN·m), which is outside the 1 percent tolerance. The answers are meant to be read from the analysis; if the owner wants hand values accepted, the tolerance of `moment-a` needs widening.
- The briefs, rubrics and outcomes are English text in the task data, not in the message catalog of `packages/i18n`.
- No defect was found in `packages/model` or `packages/solver`.
